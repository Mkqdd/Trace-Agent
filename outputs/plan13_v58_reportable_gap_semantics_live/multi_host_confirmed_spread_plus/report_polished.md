- **一句话结论**：以 ws-eng-02 为起点的可疑多主机信标传播（Suspected multi-host beacon spread）事件，已通过 JA4 指纹信标、罕见域名解析、可疑进程执行及 PsExec 远程服务创建与 ws-eng-05 的回连行为，形成从单点异常到多资产外联的完整证据链

## 1. 事件结论与当前判断

当前判断为“确认安全事件”。研判把握为高，最终置信度 94%，可以交付事件级结论。种子告警提示为“Suspected multi-host beacon spread”，事件簇已经从单点异常演进到高风险阶段的多资产范围。主证据链覆盖了从罕见域名解析、TLS 信标命中与复连、可疑进程执行，到横向移动远程服务创建以及第二台主机对同一 C2 基础设施回连的完整过程。该证据链足以支撑事件成立，同时剩余候选扩线、反证和缺口将作为报告边界在后文呈现。

需要明确的是，“确认安全事件”代表当前证据已达到交付门槛，不等于已经确认攻击者完全控制主机、恶意软件完整执行或持久化驻留。当前结论允许运维人员据此启动隔离和深入核查，但更强结论仍受限于未闭合缺口以及尚未完成的候选资产验证。

## 2. 事件过程与关键时间线

事件从 2026-07-14 01:04:00 UTC 开始，资产 ws-eng-02 对罕见域名 sync-cdn-notify.net 发起 DNS 解析。仅 6 分钟后，在 01:10:00 UTC，ws-eng-02 以 JA4 指纹 t13d1516h2_2ba4190accc0_13fe129f5abc 与 sync-cdn-notify.net 和外部 IP 203.0.113.77 建立可疑 TLS 信标连接，触发种子告警。可见信标行为并未停止：在 01:14:20 UTC，ws-eng-02 再次连接至同一套 sync-cdn-notify.net 和 203.0.113.77 的命令与控制基础设施。

随后，在 01:18:00 UTC，ws-eng-02 上出现可疑执行事件，rundll32.exe 从用户可写路径加载了 DLL 加载线索，时间点紧接信标序列之后。到 01:21:10 UTC，ws-eng-02 通过 PsExec 向 10.70.3.45（对应 ws-eng-05）发起远程服务创建告警，构成显著的横向移动信号。又过约 7 分钟，在 01:28:40 UTC，第二台资产 ws-eng-05 也以与种子告警相同的方式，连接至同样的外部基础设施 sync-cdn-notify.net 和 203.0.113.77，形成闭环。

在主线推进之外，存在一条候选扩线线索：JA4 指纹 t13d1516h2_2ba4190accc0_13fe129f5abc 在其他资产上的匹配情况属于待验证范围，当前不应视为已确认的更大规模传播。

## 3. 关键证据判断

当前结论成立依赖一条从网络信标向主机执行和横向移动自然延伸的证据链。首先，ws-eng-02 在极短时间内先后完成罕见域名解析、命中 JA4 指纹的 TLS 信标以及随后的重复连接，表明通信并非一次性误报或偶然行为，而具有保持连接和回连特征。其次，信标连接后紧随 rundll32.exe 可疑执行，虽然目前缺少该 DLL 的落地文件路径哈希和完整命令行，但时序紧邻且位于用户可写路径，增加了主机侧载荷投递的合理怀疑。第三，PsExec 远程服务创建将攻击面从 ws-eng-02 扩展至 ws-eng-05，而 ws-eng-05 在远程服务事件后短时间内即连接同一套 C2 基础设施，形成有序的横向推进-信标闭环。这些要素均来自已确认的主链事实，没有被候选或边界状态削弱。

然而，也有一些更强结论在当前不成立。例如，由于未显式检查补丁、维护窗口或共享基线等反证，还不能排除远程服务创建背景中存在合规运维操作的可能性。同时，rundll32.exe 的执行证据尚缺少关于 DLL 的详细落地和进程树上下文，因此在当前不能得出恶意软件完整执行或可靠控制的结论。整体而言，当前证据足以客观支持“确认安全事件”，但将结论升级至攻击者全链路控制或长期驻留的程度，仍受这些缺口的约束。

## 4. 影响范围、候选对象与外部基础设施

已确认受影响资产是 ws-eng-02 和 ws-eng-05，两者均需要隔离和取证。ws-eng-02 作为种子资产，从一开始就参与域名解析、信标、执行和横向动作，而 ws-eng-05 作为横向移动后回连 C2 的资产，已被纳入确认受影响范围。与之关联的内部地址还包括 10.70.3.12 和 10.70.3.45，它们作为事件链中出现的内部 IP，需要在排查过程中加以监控和封锁。

候选扩线范围目前集中在 JA4 指纹 t13d1516h2_2ba4190accc0_13fe129f5abc 在其他资产上的命中情况。这些候选资产当前不能说已受确认影响，只是有待验证线索，需要通过进一步检索才能确定是否存有同指纹信标。在外部基础设施方面，核心通信目标为域名 sync-cdn-notify.net 和 IP 203.0.113.77。它们是主证据链中反复出现的外联对象和关联基础设施，不能写作已受影响的内部资产，应作为排查封禁对象和威胁情报补充来源加以处置。

## 5. 反证、替代解释与未闭合缺口

当前报告尚未发现明确的反证或完全良性替代解释。种子告警命中的 JA4 指纹与罕见域名的组合，以及短时间内先后在两个不同主机上对外联基础设施的回连行为，都使无意或共享基础设施误报的概率大幅降低。即便如此，仍有多个未闭合缺口限制了更强结论的成立。其中，远程服务创建事件尚未与补丁窗口或维护基线进行比对，因此不能完全排除该动作来自正常运维操作的残余影响。而在主机执行层面，rundll32.exe 的具体命令行、落地文件路径和父子进程等深层证据尚未获取，导致无法得出恶意代码完整加载与稳定执行的结论。

另外，围绕当前枢轴指标的显式扩线还未完成，无法确认是否存在同指标在更大范围内的复现。外部基础设施的公开威胁情报背景也未补充，使其暂时只能作为关联设施而非归因锚点。这些缺口并不是否定当前事件交付的理由，而是明确当前阶段的分析上限，提示后续行动需要逐个闭合。

## 6. 处置建议与后续核查

- **隔离与监控受确认影响资产**：针对 ws-eng-02 和 ws-eng-05，通过 EDR 或系统事件日志（如 Windows Event Log 的服务创建、进程启动和网络连接事件）获取落地文件哈希、完整命令行和父子进程链，验证攻击者执行和驻留范围。
- **封禁外部基础设施**：在防火墙、安全网关或代理设备上对 203.0.113.77 和 sync-cdn-notify.net 进行封禁，并在 DNS 日志和代理访问日志中回溯同时间窗内其他资产对这两个目标的连接，确认是否遗漏受影响主机。
- **扩大横向移动排查**：利用 PsExec 远程服务创建产生的 10.70.3.45 指标，检索安全日志或 Sysmon 中的服务创建和远程连接事件，重点确认 ws-eng-02 与 ws-eng-05 之外是否还存在更多被远程服务写入的资产。
- **枢轴指标扩线**：以 JA4 指纹 t13d1516h2_2ba4190accc0_13fe129f5abc 和域名 sync-cdn-notify.net 为枢轴，在流量传感器或解密 SSL 日志中检索同一分析窗口内的所有命中，确认是否存在其他内网资产出现相同信标行为。
- **外部情报关联**：将 203.0.113.77 和 sync-cdn-notify.net 提交至威胁情报平台或内部知识库，补充基础设施归属、历史活动记录和家族关联，作为归因参考而非直接结论依据。
