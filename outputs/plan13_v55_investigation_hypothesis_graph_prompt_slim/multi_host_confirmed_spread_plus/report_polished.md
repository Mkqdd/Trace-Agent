## 1. 事件结论与当前判断

本次事件已确认为一起确认安全事件，研判把握为高（置信度94%）。起始告警于 2026-07-14 01:10:00 UTC 触发，源主机 ws-eng-02（10.70.3.12）向外部 IP 203.0.113.77 发起可疑 TLS 通信，命中 JA4 指纹 t13d1516h2_2ba4190accc0_13fe129f5abc，告警自带家族提示为 Suspected multi-host beacon spread。该告警触发的分析窗口为 2026-07-14 01:04:00 UTC 至 2026-07-14 01:39:20 UTC。

事件簇已从单点异常推进到多资产范围的真实威胁。在分析窗口内，共检索到 6 条偏可疑事件，围绕域名 sync-cdn-notify.net、IP 203.0.113.77 和内部地址 10.70.3.45 形成完整的攻击链。主支撑证据显示：种子主机在告警前已解析稀有域名 sync-cdn-notify.net（01:04:00 UTC），之后与外部 C2 基础设施建立 TLS 信标（01:10:00 UTC），并在告警后重新连接同一基础设施（01:14:20 UTC），随后出现可疑的 rundll32.exe 加载 DLL 的执行行为（01:18:00 UTC），进而通过 PsExec 向 10.70.3.45（ws-eng-05）发起远程服务创建（01:21:10 UTC）。第二台主机 ws-eng-05 在远程服务事件后约 7 分钟，也向同一信标基础设施发起可疑 TLS 通信（01:28:40 UTC）。主支撑证据和范围已达到确认事件交付门槛。

需要强调的是，“确认安全事件”在此处表示证据足以支撑交付事件级结论，不等于已经确认攻击者完全控制、恶意软件完整执行、横向移动闭环形成或持久化机制建立。当前结论受限于未闭合缺口和待验证候选事件，更强结论（如已观察到完全控制两台主机、已建立长期驻留）尚不成立。

## 2. 事件过程与关键时间线

分析窗口从 2026-07-14 01:04:00 UTC 开始。在该时刻，种子主机 ws-eng-02（10.70.3.12）先行解析了一个稀有域名 sync-cdn-notify.net，这发生在可疑 TLS 会话之前，属于命令与控制阶段的 DNS 解析行为。6 分钟后，即 01:10:00 UTC，种子告警触发：ws-eng-02 向外部 IP 203.0.113.77（解析自 sync-cdn-notify.net）发起 TLS 通信，命中特定 JA4 指纹，被标记为疑似多主机信标扩散行为。此事件为主支撑事件，确立了初始 C2 连接。

告警触发后，ws-eng-02 并未停止通信。在 01:14:20 UTC，该主机重新连接至同一 C2 基础设施 sync-cdn-notify.net/203.0.113.77，构成持续信标行为，进一步坐实该连接的恶意性质。约 4 分钟后，01:18:00 UTC，ws-eng-02 上出现可疑进程事件：rundll32.exe 从用户可写路径加载了一个加载器 DLL，该执行链发生在信标序列之后，属于命令与控制后的执行阶段。虽然缺乏完整的命令行参数分析、落地文件哈希和父子进程树证据，但时间序列的高度吻合将此执行事件推入主证据链。

横向移动阶段在 01:21:10 UTC 被观测到：ws-eng-02 通过 PsExec 向内部地址 10.70.3.45（即 ws-eng-05）发起远程服务创建。这是已确认的横向移动事件，直接关联种子信标流量之后的行为。随后，在 01:28:40 UTC，第二台主机 ws-eng-05（10.70.3.45）也向原始信标基础设施 sync-cdn-notify.net/203.0.113.77 发起可疑 TLS 通信，构成第二台受信标影响的主机。至此，攻击链从单机信标扩展到两机协同外联，符合“多主机信标扩散”的家族提示。

在主链之外存在候选扩线事件，需标明为待验证线索。ws-eng-05 在 01:32:10 UTC 解析了另一个稀有域名 cdn-notify-edge.net，该域名未出现在种子告警中。随后在 01:36:00 UTC，ws-eng-05 通过 TLS 连接至 cdn-notify-edge.net 解析出的外部 IP 198.51.100.44，构成第二组可疑外联目标。最终，在 01:39:20 UTC，ws-eng-05 通过 WMI 向内部地址 10.70.3.90（候选资产 ws-eng-09）发起远程进程创建，形成候选横向移动行为。这3条候选事件尚未完成独立验证，不能并入已确认主链，但为扩线排查提供了明确方向。

## 3. 关键证据判断

当前结论之所以成立，核心在于证据链的时间和因果关系高度闭合。种子告警之前已有 DNS 解析铺垫（sync-cdn-notify.net），说明该连接并非偶然或误报。告警本身命中了明确的 JA4 指纹，且告警后同一主机立即重连同一基础设施，这是活跃 C2 信标的典型特征，难以用正常业务行为解释。仅数分钟后，同一主机出现可疑 rundll32.exe 加载 DLL 的执行行为，在时间序列上与信标通信构成紧密相邻关系。更关键的证据是，ws-eng-02 在完成信标序列后，立即通过 PsExec 向内部另一主机 ws-eng-05 发起远程服务创建。这一横向移动事件直接关联信标主机，符合规范化的横向移动模式。而 ws-eng-05 在收到远程服务事件后仅约 7 分钟，也向同一外部基础设施发起 TLS 信标通信，构成清晰的“信标-横向移动-第二主机信标”链条。这种严格的时序和拓扑闭合，使得孤立误报或业务误判的概率极低。

然而，若干更强结论当前仍不成立。首先，没有直接证据表明已观察到获得 ws-eng-02 或 ws-eng-05 的完全控制权。虽然观测到 rundll32.exe 加载 DLL 的可疑执行，但缺少对该进程的命令行参数、落地文件完整路径、以及进程树父子关系的验证，无法确认该 DLL 是否成功执行恶意载荷。其次，没有证据表明横向移动后续在 ws-eng-05 上成功部署了持久化机制或完成了二次载荷投递。ws-eng-05 的信标通信本身虽已确认，但主机侧的恶意软件驻留、注册表修改、计划任务创建等持久化指标尚未检索。第三，候选外联目标 cdn-notify-edge.net 和 198.51.100.44 尚未经过外部情报验证，不能确认为第二组 C2 基础设施，只能暂作候选排查线索。此外，种子告警自带的家族提示 Suspected multi-host beacon spread 提供了重要的辅助判断，但其本身不构成强归因，缺乏对该家族工具的具体行为特征、持久化模式和横向移动手段的外部情报印证。

## 4. 影响范围、候选对象与外部基础设施

当前已纳入确认受影响范围的资产为 ws-eng-02（10.70.3.12）和 ws-eng-05（10.70.3.45）。ws-eng-02 是种子告警的源主机，观测到完整的信标解析、TLS 信标、告警后重连、可疑进程执行和 PsExec 横向移动发起行为。ws-eng-05 是横向移动的目标主机，观测到向同一 C2 基础设施发起信标通信的行为。两台主机均需立即隔离和取证，不应再视为正常业务资产。

## 5. 反证、替代解释与未闭合缺口

ws-eng-05 上存在两条背景与替代解释事件，需要用于收窄结论边界。在 01:24:00 UTC，ws-eng-05 上开始了已批准的 SCCM 补丁暂存活动，属于维护窗口内的正常管理员行为。在 01:26:00 UTC，该主机从 download.windowsupdate.com（解析至 13.107.246.45）下载了 Windows 更新内容，同样属于已批准的补丁下载流量。这两条事件构成了针对 ws-eng-05 上可疑流量的良性解释方向。然而，这两条背景解释不能独立推翻主证据链，因为 ws-eng-05 的信标通信（01:28:40 UTC）指向的是 sync-cdn-notify.net/203.0.113.77，而非 Microsoft 更新端点。SCCM 补丁暂存活动和 Windows 更新下载所涉及的外联目标与 C2 基础设施完全不同。因此，这两条替代解释仅能说明 ws-eng-05 在分析窗口内同时存在正常维护活动，但不能解释其为何连接至种子告警相同的关联外部基础设施。它们的存在限制了我们可以断言“ws-eng-05 的所有流量均为恶意”的范围，但不影响“ws-eng-05 向 C2 基础设施发起信标通信”这一核心事实的成立。

当前事件存在若干未闭合缺口，直接限制更强结论的成立。首先，扩线得到的 3 条候选事件（候选 DNS 解析 cdn-notify-edge.net、候选 TLS 连接 198.51.100.44、候选 WMI 横向移动至 10.70.3.90）尚未完成独立验证，这意味着第二组 C2 目标和第三次横向移动的假设无法得到证实。其次，仍未围绕当前 关键关联指标 做显式扩线，无法确认 sync-cdn-notify.net、203.0.113.77 或同一 JA4 指纹是否在分析窗口内在更大范围的资产上复现，这限制了影响面的判断。第三，缺乏对该家族工具和外部基础设施的公开技术背景补充，无法判断这些指标是已知威胁、基础设施级别解释还是偶发现象。第四，虽然已关闭了执行链缺口（确认存在可疑 rundll32.exe 加载 DLL 和 PsExec 横向移动），但主机侧持久化、内存取证、文件系统残留等执行后证据仍未补齐，这意味着不能确认恶意软件完整执行或驻留成功。这些缺口的共同效果是：当前结论可以确认事件成立且多主机受影响，但不能确认已观察到建立长期驻留、已完成数据外传、或已控制第三台主机。
