## 1. 事件结论与当前判断

本次调查确认了一个高危级别的多主机信标扩散安全事件。种子告警于 2026-07-14 01:10:00 UTC 首次触发，提示 `ws-eng-02` 存在可疑的多主机信标扩散行为，命中恶意JA4指纹 `t13d1516h2_2ba4190accc0_13fe129f5abc`，目标为外部基础设施 `203.0.113.77` 和域名 `sync-cdn-notify.net`。随后的关联分析证实，`ws-eng-02` 在种子告警前后与该C2基础设施维持着稳定的TLS信标通信，并在信标会话期间加载了来自用户可写路径的可疑DLL，随后通过PsExec向 `ws-eng-05` 发起远程服务创建。在横向移动事件发生数分钟后，`ws-eng-05` 也开始与完全相同的C2基础设施建立TLS连接，这构成了攻击链从单一入口扩散至第二台主机的完整闭环。

当前结论仅限定为多主机信标扩散事件，即已观察到成功建立对两台工作站的C2通信信道，并完成了至少一次横向移动。尚不具备充分证据支持更强的结论，例如已观察到获得完全系统控制权、已实现持久化驻留或在 `ws-eng-05` 上完成了可疑执行活动闭环。剩余的候选扩线事件和未闭合缺口为当前判断的边界，它们不会推翻已确认的事件结论，但限制了影响范围和攻击深度的最终评估。

## 2. 事件过程与关键时间线

事件起点为 2026-07-14 01:04:00 UTC，种子工作站 `ws-eng-02` 解析了一个稀有域名 `sync-cdn-notify.net`，此举为后续的恶意TLS会话埋下伏笔。六分钟后，即 01:10:00 UTC，种子JA4告警正式触发，确认 `ws-eng-02` 向该域名解析所得的外部IP `203.0.113.77` 发起了命中恶意指纹的TLS加密通信，这标志着C2信标信道的建立。在告警后的 01:14:20 UTC，`ws-eng-02` 再次与同一C2基础设施重连，表明信标行为是持续性的，并非一次性网络连接。

## 3. 关键证据判断

当前确认的事件结论建立在一条前后连贯、逐步推进的证据链上。种子告警所触发的恶意JA4指纹 `t13d1516h2_2ba4190accc0_13fe129f5abc` 及其关联的 `sync-cdn-notify.net` 和 `203.0.113.77`，是整个调查的核心锚点。`ws-eng-02` 在告警前后的多次DNS解析和TLS重连行为证实了该C2信道并非孤立或误报，而是具有周期性和重连信标的典型特征，这一点由 `evt-801`、`evt-802`、`evt-803` 构成的时间序列所印证。

将C2通信与主机侧行为串联起来，是让研判把握达到“高”的基石。`evt-804` 观测到的 `rundll32.exe` 从用户可写路径加载DLL的事件，时间点紧随信标会话之后，形成了典型的“信标建立-载荷执行”模式，为可疑执行活动提供了主机层的可疑线索。而 `evt-805` 和 `evt-808` 之间的因果关系，则是确认多主机扩散的关键：`ws-eng-02` 在 01:21:10 UTC 通过PsExec操作了 `ws-eng-05` 所在的内网地址 `10.70.3.45`，七分钟后 `ws-eng-05` 便连接到了完全相同的C2基础设施 `sync-cdn-notify.net` 和 `203.0.113.77`，时间顺序和逻辑链条高度一致，强烈支持攻击者通过PsExec将信标能力复制给了第二台主机，而非巧合或独立感染。

尽管如此，我们仍需谨慎划定当前证据所能支撑的结论上限。首先，虽然观测到可疑的DLL加载，但缺乏该DLL的落地文件、进程命令行参数、内存取证或父进程链等更丰富的主机证据，因此不能判定攻击载荷已完整执行，也不能确认其具体恶意功能。其次，横向移动的证据依赖于网络层的PsExec远程服务创建告警，但并未在 `ws-eng-05` 上发现对应的服务二进制落地、磁盘剩余文件或后续的载荷执行痕迹，因此只能确认存在横向推进线索信道已被建立和使用，但不能判定 `ws-eng-05` 已被攻击者完全控制。

## 4. 影响范围、候选对象与外部基础设施

已确认受影响资产为两台工作站：`ws-eng-02` 和 `ws-eng-05`。`ws-eng-02` 是整个事件的起点和横向移动的源点，同时存在C2外联、可疑进程执行和远程服务创建三重行为，需要纳入确认受影响范围并立即隔离和取证。`ws-eng-05` 作为横向移动的目标，在极短时间内加入了同一C2信标网络，其外联行为已被确认为事件时间线的一部分，同样需要隔离和取证。两台资产构成了当前已确认的信标扩散范围。内部地址 `10.70.3.12` 和 `10.70.3.45` 分别是 `ws-eng-02` 和 `ws-eng-05` 的源地址，在当前证据图中主要作为已确认的关联内部地址出现，用于追踪通信关系。

在候选扩线层面，存在数个待独立验证的对象和资产。候选资产 `ws-eng-09`，其关联内网IP `10.70.3.90` 出现在 `ws-eng-05` 发起的WMI远程进程创建候选事件中，该事件意味着可能的第三跳横向移动，但当前完全处于待验证状态。候选外联目标包括域名 `cdn-notify-edge.net` 和IP `198.51.100.44`，二者出现在 `ws-eng-05` 的后续DNS和TLS会话候选事件中，可能构成第二C2信道或攻击者基础设施的扩展。值得注意的是，JA4指纹 `t13d1516h2_2ba4190accc0_13fe129f5abc` 不仅在已确认事件中出现，也在候选扩线中被视为一个扩展查询候选对象，日后围绕该指纹的检索可能揭示更广泛的感染面。

核心外部基础设施是已确认事件中反复出现的两个实体：IP `203.0.113.77` 和域名 `sync-cdn-notify.net`。它们是C2信标通信的接收端，在多台主机上表现出恶意行为模式的收敛。作为外部基础设施，它们不能被描述为受影响资产，而应被视作攻击者关联的C2节点，需要在边界上进行排查和封禁。背景基础设施则包括 `download.windowsupdate.com` 及其对应的IP `13.107.246.45`，它们在 `ws-eng-05` 上的活动出现在补丁维护窗口中，作为已知合法的Windows更新端点提供背景上下文，不纳入恶意威胁范畴。

## 5. 反证、替代解释与未闭合缺口

在分析所有证据的同时，我们也识别出了可能削弱更强结论的替代解释和背景信号。在横向移动事件发生后，目标主机 `ws-eng-05` 上随即出现了经批准的SCCM补丁部署活动，时间窗口为 01:24:00 UTC 至 01:26:00 UTC，包括补丁暂存和与 `download.windowsupdate.com` 及 `13.107.246.45` 的通信，这两个端点均为微软官方更新基础设施。这一维护窗口为 `ws-eng-05` 上的部分管理员活动提供了良性的背景解释，可能覆盖了横向移动后攻击者可能利用的某些行为模式。然而，`ws-eng-05` 与核心C2基础设施 `sync-cdn-notify.net` 和 `203.0.113.77` 的通信发生在维护窗口开启之后，且该通信的目标与已知合法端点完全不同，因此维护背景只能用于收窄边界，解释部分系统活动，并不能替代或否认已确认的恶意信标事件。

另一处需要保守对待的是横向移动行为的定性。从 `ws-eng-02` 到 `ws-eng-05` 的PsExec远程服务创建虽然高度可疑，并与后续的恶意信标时间线紧密衔接，但如果缺乏 `ws-eng-05` 上对应服务二进制或命令行的落地痕迹，我们无法绝对排除该远程服务创建是管理员脚本或软件分发系统异常调用的极小可能。但鉴于它与恶意C2通信的直接时间关联和完整性，这一替代解释尚不能成立更强的反驳论证。这也直接指向了未闭合缺口的核心内容：我们缺失主机侧的持久化、服务落地文件、注册表变更等确定性证据。执行链的细节缺口限制了将结论从“信标扩散”升级为“主机完全控制”。

当前有若干关键缺口限制着我们对事件的全面理解。扩线集群范围的缺口表明，尚未以 `sync-cdn-notify.net` 和 `203.0.113.77` 为pivot在全网范围内检索是否存在更多主机的同类信标行为，因此当前确认的两台主机可能只是感染全貌的冰山一角。候选事件的独立验证缺口则指出，`ws-eng-05` 上涉及 `cdn-notify-edge.net` 和 `10.70.3.90` 的多条候选事件尚未经过情报交叉比对、本地指纹匹配或流量内容验证，不能并入主事件范围。此外，外部技术背景的缺失意味着我们尚不清楚 `sync-cdn-notify.net` 和该JA4指纹在公开情报中的确切家族归属、工具栈和已知攻击者画像，这限制了归因和基础设施解释的深度。
