## 1. 事件结论与当前判断

本次调查的起点是一条来自 2026-06-24 15:02:00 UTC 的种子告警，标识为“Possible web beacon without host corroboration”，涉及内部资产 10.61.2.20，即 web-app-02。告警触发指纹为 JA4 指纹 t13d1517h2_22adbe210bc1_11cae1281e22，表明通过 TLS 协议向外部 IP 198.51.100.177 建立了疑似 Web Shell 信标连接。

当前分析形成的中等置信度判断是：web-app-02 上发生了一系列具有时间关联性和行为连贯性的可疑事件，从管理门户的主动利用尝试，到对外部域名的 DNS 解析，再到建立 TLS 信标会话并重复外联，这些环节构成了一条逻辑自洽的主证据链。该链路中的外部基础设施 auth-edge-panel.net 和 198.51.100.177 是当前事件簇的核心关联对象。

尽管如此，本案目前仍被定为“可疑事件，建议继续复核”而非确认安全事件。原因在于，虽然外联模式与可能的 Web Shell 或 beacon 行为相符，但缺少主机侧进程、命令行、落地文件和持久化等直接执行证据。同时，存在计划内补丁部署和维护窗口等可解释为正常业务活动的背景信号，关联资产 web-app-05 的相似外联也未匹配到本地告警。因此，事件影响范围和完整攻击链尚未得到充分确认。

## 2. 事件过程与关键时间线

本次事件的时间窗口为 2026-06-24 14:50:00 UTC 至 2026-06-24 15:50:00 UTC，已确认的主线事件均集中在资产 web-app-02 上。整个过程从面向管理门户的初始利用请求开始，逐步向外联和信标行为演变。

14:50:00 UTC，web-app-02 的面向公网服务收到针对管理门户的 exploit 请求，这是事件时间线的第一环。紧接着在 14:54:00 UTC，第二波利用请求出现，使用了不同的来源 ASN 和载荷家族。随后在 14:58:30 UTC，该资产首次对外部域名 auth-edge-panel.net 进行了 DNS 解析，这一行为发生在利用尝试之后，时间衔接紧密。

关键的告警事件出现在 15:02:00 UTC，种子 JA4 告警匹配到一条疑似 Web Shell 的 TLS beacon，目标为 198.51.100.177，所关联域名正是此前被解析的 auth-edge-panel.net。15:06:40 UTC，同一资产再次向同一外部基础设施发起连接，进一步强化了这条外联链路的可疑程度。此后，主线上还有一条已确认的观察：在分析窗口结束时，由于 web-app-02 未启用脚本块日志，导致主机侧的命令细节不可用，这构成了当前证据链上的一个结构性缺口。

此外，存在若干待验证的候选扩展线索。15:10:00 UTC，web-app-02 解析了与 auth-edge-panel.net 同属一组基础设施的兄弟域名 cdn-auth-edge.net，并在 15:12:30 UTC 与该域名建立了一次 TLS 会话，但因缺乏主机佐证而无法明确其性质。在更晚的时间点，15:30:00 UTC 和 15:32:20 UTC，另一台资产 web-app-05 也分别解析了 cdn-auth-edge.net 并建立了与 198.51.100.177 的短时 TLS 连接，但由于该资产上没有匹配的本地告警，其是否属于同一事件仍需独立验证。还有一台资产 web-app-04 在 15:24:20 UTC 通过扫描器遥测厂商域名 scanner-cdn.example 访问了同一个外部 IP 198.51.100.177，这更倾向于共享托管或扫描行为的背景解释。

## 3. 关键证据判断

当前确认 web-app-02 存在可疑安全事件的核心依据，在于其行为序列与典型的 Web 服务器沦陷后外联模式高度吻合。事件的起点是两次针对管理门户的 exploit 请求，分别发生在 14:50:00 和 14:54:00，这为可能的初始入侵提供了入口背景。在此之后，资产在 14:58:30 主动解析了域名 auth-edge-panel.net，随后的 15:02:00 和 15:06:40，分别出现了与该域名关联 IP 198.51.100.177 的 TLS 信标会话和重复外联。这种 DNS 解析与后续加密外联之间的紧密时序关联，是判断该链路并非孤立噪声，而是具有入侵后外联行为特征的重要依据。种子告警所标识的 JA4 指纹和“Possible web beacon without host corroboration”提示，进一步强化了该外联为可疑 Web Shell 通信的研判。

然而，现有的证据尚不能支撑已观察到获得持久控制、已执行任意代码或已发生横向移动等更强的结论。这一限制主要来自三方面。其一，主机侧遥测显示，在 15:15:30，web-app-02 的 Web 工作进程没有产生可疑的子进程活动，这直接削弱了执行后门的推测。其二，由于 web-app-02 未启用脚本块日志记录，整个分析窗口内都无法获取主机命令行的直接证据，使得执行链的验证无法闭环。其三，对于关联资产 web-app-05 和 web-app-04 上的相似流量，目前分别缺乏本地告警匹配和倾向于解释为扫描器遥测或共享托管背景，这使得事件范围尚未超出 web-app-02 本身。因此，虽然主链证据有力地指向了一起利用和外联事件，但更高置信度的攻击链认定仍待填补执行确认和范围扩展验证这两项缺口。

## 4. 影响范围、候选对象与外部基础设施

已确认受影响范围目前局限于单一资产 web-app-02，即内网地址 10.61.2.20。该资产是整个主证据链的核心，承载了从初始利用请求到 DNS 解析、再到 TLS 信标外联的完整可疑行为序列。所有已确认的可疑事件均与该资产的内部 IP 直接关联，使其成为当前事件簇中唯一需要采取强制隔离和取证措施的节点。

除已确认资产外，调查中浮现了若干待验证的候选对象。资产 web-app-05 在 15:30:00 和 15:32:20 分别解析了兄弟域名 cdn-auth-edge.net 并向 198.51.100.177 发起了 TLS 连接，但因没有匹配本地告警，目前只能将其列为需要重点复核的候选资产，不能简单地归入已受影响范围。资产 web-app-04 在 15:24:20 通过 scanner-cdn.example 访问同一外部 IP 的行为，目前更倾向于解释为共享托管环境下的正常扫描流量，而非攻击事件波及，但仍需一次验证才能最终排除。

事件中的核心外部基础设施是域名 auth-edge-panel.net 和 IP 地址 198.51.100.177，它们是在主证据链中反复出现且与关键告警直接关联的对象，应作为后续排查和封禁决策的核心指标。另一个域名 cdn-auth-edge.net 作为同组基础设施上的兄弟域名，在 web-app-02 和 web-app-05 的流量中均有出现，但目前被定位为关联排查对象。此外，扩线过程中出现了多个安全厂商或威胁情报平台的域名，如 checkpoint.com、thedfirreport.com 和 www.trendmicro.com 等，这些均属于情报来源或背景上下文，不应被错误地写成受影响资产或关联外部基础设施。

## 5. 反证、替代解释与未闭合缺口

本案中存在着若干需要正视的反证和替代解释，它们限制了直接把事件定性为确认安全事件并扩大影响范围的推论。首先，计划内的管理门户补丁部署窗口与利用请求的时间段存在重叠，这意味着部分针对管理门户的请求，特别是属于特征变化和不同 ASN 来源的第二次请求波次，在逻辑上存在被解释为未经调校的补丁审计扫描流量，而非纯恶意利用尝试的可能性。其次，web-app-02 在 15:15:30 的主机遥测结果显示，其 Web 工作进程在分析窗口内没有产生可疑子进程活动，这与典型的 Web Shell 投递后立即产生脚本或命令进程的模式不符，虽然不否定应用层 Web Shell 的存在可能，但降低了常规可疑执行活动链的置信度。此外，在 15:34:00，更新后的 WAF 规则已经成功阻断了针对管理门户的重复载荷，表明安全控制措施在此次事件中仍然有效，这可能限制了后续深入利用的窗口。
