## 1. 事件结论与当前判断

当前分析窗口（2026-06-20 10:04:30 UTC 至 2026-06-20 11:18:00 UTC）内，已形成以 ws-legal-03（IP 10.44.1.18）为中心的可疑事件簇。种子告警于 2026-06-20 10:12:00 UTC 命中，提示 ws-legal-03 向 auth-queue-sync.net（IP 198.51.100.131）发起异常 TLS 会话，命中 JA4 指纹 t13d190900_7711aa22bb33_9911ccddee77，标记为“Suspicious shared-infra beacon requiring review”。该资产在告警后仍于 10:16:20 和 10:21:40 两次复用同一域名及共享基础设施路径，表现出持续性外联特征。

## 3. 关键证据判断

构成当前结论的主证据链主要建立在三个已确认事件和若干辅助事实上。种子告警（evt-702）不仅提供了时间起点，更重要的是携带了明确的家族或工具提示“Suspicious shared-infra beacon requiring review”，使外联行为的可疑性建立在一个经过规则匹配的证据视图上，而不是纯粹网络流量异常。告警之后的两条后续连接（evt-703 与 evt-704）证明 ws-legal-03 在告警生成后并未中断对同一域名的访问，而是复用相同路径持续回连，这个持续的时序结构是支撑当前结论为什么偏向“可疑”而非“误报”的核心原因。同时，auth-queue-sync.net 被识别为罕见域名且实时解析指向共享托管 IP 198.51.100.131，形成了与“共享基础设施信标”这一家族提示相匹配的基础设施画像。

然而，证据链在主机侧存在明显断层。ws-legal-03 在分析窗口内缺少命令行遥测，这一资产上下文事实直接导致无法确认是否存在恶意剧本执行、脚本落地、计划任务添加或注册表持久化等攻击行为。这意味着，即使网络侧一再表现持续性外联，也无法推导“攻击者实际获得了执行权”这一更强结论。缺失的主机证据限制了最终判断的上限：当前仅能确认“存在可疑共享基础设施信标类外联”，而不能将其升级为已确认的 C2 信道、恶意软件植入或攻击者控制。

另外，必须注意到，ws-legal-03 上存在一条与首次可疑 TLS 会话时间重叠的浏览器 SSO 扩展更新事件（evt-711），并且同一资产在相近窗口内还出现了访问 login.microsoftonline.com 的正常身份认证流量（evt-712）。这些背景或候选边界事件说明，部分 TLS 会话可能被浏览器更新线程或身份认证流水线触发，不能完全排除共享基础设施上的正常业务 SaaS 组件被误读为信标。不过，这些事件只能用来限制结论边界，并不足以推翻已形成的可疑事件簇。综合来看，主机侧证据缺失、浏览器更新背景以及共享基础设施的多租户性质是制约当前结论强度并设定“待人工复核”状态的三条核心界限。

## 4. 影响范围、候选对象与外部基础设施

目前纳入确认受影响范围的资产仅为 ws-legal-03，其对应内网 IP 为 10.44.1.18。该资产在整个分析窗口内表现出三次对统一外部目标的连续外联，且首次 DNS 解析早于种子告警近 8 分钟，说明其初始外联意图并非由告警事件被动触发，而是源自资产内部的某种先期触发条件。ws-legal-03 应被作为当前事件的物理起点，优先进行隔离和主机取证。除 ws-legal-03 外，ws-legal-09（IP 10.44.1.29）和 ws-legal-12（IP 10.44.1.42）作为待确认候选资产一并列入扩线核查范围，当前不能将其表述为已受影响，也不能将它们的网络活动视为同一事件的确认延伸。对这两个资产的判断取决于后续是否能够在更长时间窗内捕获到类型一致、时序稳定且复用相同 JA4 指纹的重现行为。

## 5. 反证、替代解释与未闭合缺口

本事件在论证过程中识别出多条可解释为正常业务行为的信号，这些信号独立构成对“确认安全事件”结论的降级因素。ws-legal-03 在首次可疑 TLS 会话期间同时发生了已批准的 SSO 浏览器扩展更新，并且同一资产在相近时段内产生了向 login.microsoftonline.com 及对应 IP 20.190.160.22 的 Microsoft 身份认证流量。这种时间窗口重叠和业务流重叠，使得部分 TLS 会话存在由浏览器身份流水线或更新回调触发的可能，而不是攻击者植入的信标逻辑。此外，ws-legal-09 的活动场景更为典型：该资产虽然也触及了同一共享 IP 198.51.100.131 上的 cdn-auth-queue.net，但同时在同一 IP 上访问了授权身份缓存域名 identity-cache.vendor.example，该连接被标记为浏览器 SSO 特征，极大降低了 cdn-auth-queue.net 通信的可疑性。基础设施侧，外部情报也明确表明 198.51.100.131 在同一周已托管过多个无关客户域，共享托管属性与信标特征之间存在内在张力，使得单一主机的 TLS 异常在纯网络视图下无法成为定性的决定性证据。

未闭合缺口同样直接限制了更强结论的成立。最重要的缺口是主机侧执行证据缺失：ws-legal-03 在窗口内缺少命令行遥测，ws-legal-09 同样缺少 EDR 命令级日志。两条遥测缺口分别对应一个已确认受影响资产和一个待确认候选资产，导致无法闭环判断是否有载荷执行、脚本下载、进程创建或持久化动作。另一条缺口指向关联资产的真正影响范围，即 ws-legal-09 和 ws-legal-12 是否在更大时间窗口内表现出类型一致的信标行为仍未定论。此外，seed alert 自带的家族或工具提示“Suspicious shared-infra beacon requiring review”虽然提供了基础假设方向，但目前尚缺少该家族在当前共享基础设施环境下的公开技术报告或威胁情报与之映射，未能形成“已验证家族归因”的闭环。这些缺口的存在并不意味着否定当前可疑事件簇的有效性，而是划定了一个清晰的上限：在人工复核完成主机取证、扩线搜索和家族情报验证之前，不能将当前线索升级为已有攻击者控制、横向移动或长期驻留的确认结论。
