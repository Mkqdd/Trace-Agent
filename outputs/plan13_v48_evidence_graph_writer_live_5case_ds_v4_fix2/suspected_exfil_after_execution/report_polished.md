## 1. 事件结论与当前判断

本次调查基于一条针对研发终端 ws-rnd-04 的种子告警展开，告警在 2026-06-03 16:40:00 UTC 命中可疑 TLS Beacon 并带有 JA4 指纹 t13d190900\_44ac2200b3c1\_ab11cd22ee44，同时附带 Suspected cloud-storage exfil chain 家族提示。调查窗口自 2026-06-03 16:28:00 UTC 至 2026-06-03 17:24:40 UTC，分析团队通过在时间窗内对种子指标（源 IP 10.90.2.44、目标 IP 198.51.100.144、域名 files-sync-share.net 及 api.files-sync-share.net）进行关联扩线，获取了多条构成完整攻击链的可疑事件。主证据链表明 ws-rnd-04 从 DNS 解析、命令行与压缩执行、文件暂存到大规模加密上传的完整过程高度一致且时间紧密：PowerShell 调用用户配置文件下的 staging 脚本后，7z 压缩工具对项目空间进行归档，随后短时间内产生约 640 MB 的出站上传至存储边缘，最后再由同一主机的 DLP 记录确认该加密传输不可解析。上述观察使得主证据达到确认交付门槛，判断整起事件为高危的确认安全事件。

尽管当前已具备事件成立的充分证据，但本次调查仍以保守边界呈现。报告中除了已纳入确认受影响范围的 ws-rnd-04，其他资产如 ws-rnd-09、ws-rnd-12 及各候选域名与 IP 均作为待验证或背景线索处理。对于各项证据，遵循“确认安全事件”不等于已经确认攻击者完全控制机器、横向移动闭环或长期驻留的原则，报告在反证、替代解释和未闭合缺口部分也收录了可能削弱更强结论的背景信号，供运营和安全协同人员参考。

## 2. 事件过程与关键时间线

事件最早的可疑信号出现在 2026-06-03 16:28:00 UTC，资产 ws-rnd-04 解析了罕见的存储主题域名 files-sync-share.net。随后，在 2026-06-03 16:34:20 UTC，同一资产与 files-sync-share.net 关联 IP 198.51.100.144 建立了一次短暂的 TLS 会话，该行为发生在大规模传输序列之前，性质归入命令与控制类通信。在 2026-06-03 16:40:00 UTC，种子 JA4 告警正式捕获一段针对 files-sync-share.net/198.51.100.144 的可疑 TLS Beacon，JA4 指纹匹配为 t13d190900\_44ac2200b3c1\_ab11cd22ee44。这一步构成了调查的主支撑事件。

执行阶段紧随其后。2026-06-03 16:42:30 UTC，ws-rnd-04 从用户配置文件启动 PowerShell，并调用 C:\Users\analyst\AppData\Roaming\sync.ps1 这一 staging script。紧接着，在 2026-06-03 16:44:00 UTC，同一主机通过 7z.exe 从项目工作区创建了 RND-Q2-prototype.zip 压缩包。文件暂存和外传在极短时间内完成：2026-06-03 16:45:40 UTC，该压缩包被暂存为 C:\Users\Public\Music\cache.dat，随后在 2026-06-03 16:47:00 UTC，主机向 files-sync-share.net/198.51.100.144 发起了对外的 HTTPS 大流量上传，传输量约 640 MB。分析窗口进一步记录到，2026-06-03 16:50:10 UTC 的 DLP 传感器确认了该加密外传的大小但无法解析压缩包内容。同日 16:52:30 UTC，ws-rnd-04 继续解析了同为存储边缘的兄弟域名 api.files-sync-share.net，并在 16:55:00 UTC 通过该域名的 TLS 会话完成上传后的跟随通信。

在扩线过程中，本次调查还观察到 ws-rnd-09 在 2026-06-03 17:05:00 UTC 与同一存储边缘 files-sync-share.net/198.51.100.144 产生了一次短暂 TCP 连接，但该次连接较为孤立且没有主机侧的进一步证据。调查记录还显示，2026-06-03 17:08:20 UTC，ws-rnd-09 在同一小时内存在已批准的备份任务，可能解释其部分存储型流量。此外，2026-06-03 17:12:00 UTC，ws-rnd-04 同时存在到 company-my.sharepoint.com 和 13.107.136.9 的正常企业 SharePoint 同步流量，表明该主机在攻击期间夹杂有合法业务背景流量。关于 ws-rnd-12，其于 2026-06-03 17:24:40 UTC 通过另一个 CDN 域名 filesync-cdn.example 访问了同一 IP 198.51.100.144，提示该 IP 并非仅有恶意用途。上述 ws-rnd-09 与 ws-rnd-12 的行为和候选扩线域名如 www.microsoft.com、www.vectra.ai 等均标记为待验证候选，不能直接归入已确认影响范围。

## 3. 关键证据判断

主证据链能够支撑当前确认事件的结论，核心在于 ws-rnd-04 上多个可验证行为的时序耦合、行为逻辑连贯性及与外传目标的反复确认联系。已确认事实显示，种子告警并非孤立出现，而是由早期 DNS 解析、预先 TLS 会话、脚本执行和数据打包步骤逐步推进而来，随后统一收敛于面向 files-sync-share.net/198.51.100.144 的 640 MB 上传以及兄弟域名 api.files-sync-share.net 的跟随通信。这一链条排除了偶然网络抖动的可能性，反而呈现出从环境探测到执行、从打包到上传的明确意图。DLP 事件虽然提示压缩包内容无法解析，但正是这种加密传输加上大量载荷上限的特点，从流量和 DLP 双视角强固了外传事实。

同时需要说明，当前结论并不能扩张为“已观察到获得完全会话控制”“横向移动已发生”“持久化已建立”等更强判断。主机侧的执行事实仅停留在 PowerShell 调用及脚本路径暴露，并未捕获完整的命令行参数，EDR 在此处存在遥测缺口。DLP 也未解析压缩包内具体文件清单，因此“外传数据为项目源码或知识产权”仍属推理而不是已经验证的客观事实。外部 IP 198.51.100.144 虽然作为核心基础设施出现在主链中，但其他上下文事件表明同一 IP 可能承载共享业务或 CDN 资源，因此仅凭 IP 归属不能推定为完全由攻击者独享的基础设施。综上所述，证据对本次事件成立的支撑力度充分，但结论上限应保持在“存在严重外传风险的确认安全事件”范围。

## 4. 影响范围、候选对象与外部基础设施

在本次调查窗口内，已确认纳入受影响范围的资产是 ws-rnd-04。ws-rnd-04 是种子告警的源资产，也是调查中 DNS、流量、进程、文件和 DLP 等全部主链事件的发生对象，构成了唯一具备充分证据的内部受影响节点。其他两个在扩线中出现的内部主机 ws-rnd-09 和 ws-rnd-12 仅作为候选范围登记。ws-rnd-09 虽然与 198.51.100.144 存在一次存储方向的连接，但该行为孤立、时间较晚，且主机存在已批准的备份任务，因此该连接目前仍需通过 EDR 回溯和流量日志二次验证，才能决定是否纳入受影响范围。ws-rnd-12 则通过另一供应商 CDN 域名访问了同一外部 IP，其访问情境和业务逻辑均与主链不同，当前更接近共享基础设施上的无关流量，在独立调查完成前不应标记为受事件影响资产。

外部基础设施方面，核心外联对象包括 files-sync-share.net、api.files-sync-share.net 及其关联的 IP 198.51.100.144。这组域名和 IP 不仅出现在种子告警和上传行为中，还在 DNS 解析、两个阶段的 TLS 会话以及 DLP 事件中反复出现。根据外部基础设施不应被写成受影响资产的原则，本报告将这些对象分别标记为外联域名与关联 IP，建议作为排查和封禁对象处理，并在调查期间重点关注该存储边缘上是否存在租户或账号粒度的更多痕迹。此外，company-my.sharepoint.com 和 13.107.136.9 被识别为背景对象，代表 ws-rnd-04 的常规企业 SharePoint 同步流量。其余候选域名如 attack.mitre.org、www.fortinet.com 等均来自扩线过程，当前仅保留为待验证线索，无从判断与主事件的直接因果关系。

## 5. 反证、替代解释与未闭合缺口

调查过程中出现的多条背景信号和替代解释对结论的上限形成了合理限制，但并不足以推翻主链事实。首先，ws-rnd-04 在攻击时间窗内确实产生了正常的 SharePoint 同步流量到 company-my.sharepoint.com 和 13.107.136.9，这表明资产同时承担合法业务。其次，外部 IP 198.51.100.144 被证实并非单一用途，lab 资产 ws-rnd-12 曾通过 filesync-cdn.example 访问同一 IP，增加了该地址作为共享存储或 CDN 边缘节点的可能性。此外，ws-rnd-09 在相同时间窗口存在一例存储边缘连接恰好与已授权备份任务重合，也降低了该次连接作为恶意传播证据的充分度。这些背景和替代解释虽然压缩了“所有与 198.51.100.144 的通信均为恶意”这一更强的断言空间，却并不消解主资产 ws-rnd-04 上从脚本执行到大规模上传的完整恶意行为链。

目前最关键的未闭合缺口集中在主机侧执行细节和外传内容核实两方面。EDR 未能保留完整的 PowerShell 命令行，导致 sync.ps1 的具体功能、参数和调用链不能精准重建，这也连带阻碍了对是否存在后续加载、注入或持久化操作的确定。DLP 对压缩包内容不可解析的状态，意味着尚无法确认外传文件中是否包含核心知识产权、凭据或其他敏感数据。其他缺口包括围绕 ws-rnd-09 和 ws-rnd-12 的独立验证尚未完成，以及对指纹 t13d190900\_44ac2200b3c1\_ab11cd22ee44 在同网段内的复现情况缺少全量扫描。这些缺口在总体上限制了将事件升格为“已确认横向扩散”“已观察到完整控制资产”或“外传内容已核定”等更强水平结论的可行性。

- 最后，建议与云存储安全运营或外部威胁情报团队协作，针对 198.51.100.144 和 files-sync-share.net 做外部分析，获取注册信息、历史关联域名及可能链接到的已知攻击活动。结合本地的 DLP 加密文件记录和主机暂存路径，与内部资产管理者确认文件 RND-Q2-prototype.zip 的业务敏感性。这一步将有助于准确评估数据泄漏的影响程度，并判断该存储边缘是否已作为攻击者持续外传的回收节点。
