## 1. 事件结论与当前判断

本次事件簇从一台种子工作站 ws-eng-02 出发，在分析窗口 2026-07-14 01:04:00 UTC 至 2026-07-14 01:49:00 UTC 内，逐步演进为多台主机先后与相同外部 C2 基础设施建立可疑 TLS 信标的模式。种子告警于 2026-07-14 01:10:00 UTC 触发，命中 JA4 指纹 t13d1516h2_2ba4190accc0_13fe129f5abc，并携带家族提示 Suspected multi-host beacon spread，为后续调查提供了明确起点。基于已确认的事件时间线，ws-eng-02 在信标序列后使用了 PsExec 远程服务创建，连接至 ws-eng-05，之后 ws-eng-05 在数分钟内同样访问了原始 C2 基础设施，构成了横向移动之后的多点外联闭环。据此，本报告确认这是一起已发生且仍在窗口内推演的安全事件。

事件结论目前建立在已确认主链之上，确认受影响资产数量有限且主要证据集中于信标、横向移动和可疑进程启动。由于 ws-eng-09 关联事件仍处于候选状态，且其 EDR 遥测出现降低间隙，暂时无法确认攻击者是否在第三台主机上获得了执行控制，也不能确认是否存在持久化或数据外传闭环。因此，当前结论聚焦于已确认的两个受影响资产和一组核心外部基础设施，其余扩线、反证和候选对象将在后续各节中以边界形式完整呈现，供运营团队进行补充核查。

## 2. 事件过程与关键时间线

事件起点出现在 2026-07-14 01:04:00 UTC，资产 ws-eng-02 发起了一条针对稀有域名 sync-cdn-notify.net 的 DNS 解析请求，这为后续的可疑 TLS 会话提供了关键前置信号。六分钟后，即 2026-07-14 01:10:00 UTC，同一资产向 203.0.113.77 发起 TLS 通信，触发 JA4 指纹命中的种子告警，安全监测系统将其标记为疑似多主机信标扩散。这一 TLS 信标在 2026-07-14 01:14:20 UTC 再次出现，确认 ws-eng-02 在告警之后仍然维持与同一 C2 基础设施的稳定回联，体现出周期性信标行为特征。

在信标序列之后，内部横向移动的可疑证据很快浮出水面。2026-07-14 01:18:00 UTC，ws-eng-02 上出现了可疑进程启动事件，rundll32.exe 从用户可写路径加载了一个 DLL 加载线索，该行为恰好在信标通信之后发生，形成了一条“外联-下载/执行”的典型序列。到 2026-07-14 01:21:10 UTC，安全监控再次捕获到一次高风险告警，ws-eng-02 通过 PsExec 向 10.70.3.45 发起远程服务创建，目标正是资产 ws-eng-05，这标志着攻击活动已经尝试越过种子主机边界。

冲击范围在数分钟后进一步外扩。2026-07-14 01:28:40 UTC，资产 ws-eng-05 主动发起了对 sync-cdn-notify.net 和 203.0.113.77 的 TLS 流量，表明该资产在横向移动后已建立与原始 C2 基础设施的独立信标。在更晚的时间点，ws-eng-05 还出现了若干与候选域名 cdn-notify-edge.net 及候选外部 IP 198.51.100.44 相关的通信，但这些事件目前属于候选扩线，尚未完成独立验证，仅作为待核查线索列入后续边界讨论。另外，第三台资产 ws-eng-09 在 2026-07-14 01:44:10 UTC 之后也解析了同一候选域名，并于 01:47:30 UTC 向 198.51.100.44 发起 TLS 连接，但由于 ws-eng-09 的 EDR 进程遥测于 01:49:00 UTC 被报告为降级，无法重建其执行血缘和载荷来源，因此对于第三台资产是否真正受到传播，只能在待验证范围内保留。

## 3. 关键证据判断

当前结论之所以成立，核心在于主链上几条已确认事实组成的稳定论证链。首先，ws-eng-02 在 01:10:00 UTC 的 TLS 信标告警为事件提供了精确起点，而 01:14:20 UTC 的再次外联使单次连接升级为周期性 C2 行为。其次，随后的可疑进程启动事件虽然在当前事实边界内无法提供完整命令行或落地文件哈希，但 rundll32.exe 从用户可写路径加载 DLL 加载线索 的模式与常见恶意代码执行方式高度一致，构成了目前可确认的执行线索。再次，PsExec 远程服务创建直接连接了两个主机，是已知攻击者常用的横向移动工具之一，且在时间上与信标序列紧密衔接，形成了“C2 通信 - 执行 - 横向移动”的完整动作链。最后，ws-eng-05 在远程服务创建后数分钟内同样外联到 203.0.113.77 和 sync-cdn-notify.net，完成了从初次感染到第二主机独立回联的关键跨越，使得感染扩散的推断在现有事实范围内可以稳定成立。

不过，目前能够支撑的结论仍受限于若干证据缺口。尽管已观察到 rundll32.exe 行为，但尚未获得完整的命令行参数、创建的子进程关系、持久化机制（如计划任务、注册表项或服务残留）以及落地文件的内存镜像证据，因此不能将 ws-eng-02 直接表述为“攻击者完成完全载荷执行与控制”。同样，横向移动动作仅以 PsExec 远程服务创建为依据，未发现显式横向凭证窃取、域内提权或进一步的内网扫描行为，所以不能高估攻击者的横向广度。交付结论中使用的家族提示 Suspected multi-host beacon spread 目前更多作为背景辅助，尚不构成精确归因，不能据此在本报告中声称已确认某已知恶意软件家族的特定变种。

## 4. 影响范围、候选对象与外部基础设施

已确认的受影响资产限于 ws-eng-02 和 ws-eng-05，两台主机均在时间窗口内完成信标通信和横向关系构成，需要优先纳入隔离和取证范围。ws-eng-02 同时承载了种子告警、C2 回联、可疑执行和横向移动发起动作，是整个事件链条中最关键的内部节点。ws-eng-05 虽然当前仅在网络层捕捉到外联信标，但由于其外联时间紧接横向移动之后，应被视为从种子主机扩散出的已受影响资产，后续需要补充主机侧调查以确认是否存在进一步的执行或持久化。

候选资产 ws-eng-09 和 ws-lab-02 目前不能写入已确认受影响范围。ws-eng-09 的 DNS 解析和 TLS 连接事件虽然在时间线上与 ws-eng-05 的 WMI 远程进程创建能够形成推断上的承接关系，但这些候选事件尚未经过独立验证，且 EDR 遥测降级使得执行链不可见，暂时只能作为待确认扩线线索，无法排除误报、正常管理操作或共享基础设施导致的假阳性。ws-lab-02 则主要出现在背景或替代解释事件中，其外联对象 telemetry-collector.example 和 198.51.100.44 更可能是 QA 遥测任务的一部分，目前倾向于与本次事件主体无关，但仍保留为背景资产以支持后续网络路径分析。

核心外部基础设施由 203.0.113.77 和 sync-cdn-notify.net 构成，二者在种子告警、后续信标及 ws-eng-05 外联中反复出现，属于当前唯一可以明确锁定为排查和封禁对象的外部地址组合。其他如 cdn-notify-edge.net、198.51.100.44 以及一系列候选域名 hunt.io、malpedia.caad.fkie.fraunhofer.de、thedfirreport.com、www.activecountermeasures.com、www.microsoft.com、www.safeaeon.com 等均处于候选状态，要么源于扩线查询结果，要么其关联事件尚不具备独立可验证指示物，报告只能将其列为关联基础设施或待定外联对象，不能直接视作攻击者设施。共享或背景域 download.windowsupdate.com 和 telemetry-collector.example 则属于正常业务或补丁相关上下文，用于收窄对边界事件的解释范围。

## 5. 反证、替代解释与未闭合缺口

在推进事件定性的同时，必须考虑若干已发现的反证和替代解释，这些因素决定了当前结论的上限。资产 ws-eng-05 上捕捉到的报修窗口和补丁活动构成了一条典型替代路径。2026-07-14 01:24:00 UTC 出现 SCCM 补丁部署，随后在 01:26:00 UTC 出现对 download.windowsupdate.com 和 13.107.246.45 的更新内容下载，这些事件在时间上与 ws-eng-05 第一次外联 C2 有一定重叠，虽然不能推翻横向移动与外联信标的整体论证，但提醒运营团队，ws-eng-05 上部分系统活动可能混杂了正常维护操作，不能将 ws-eng-05 上所有罕见域名解析或网络流一律归因于恶意行为。此外，198.51.100.44 已通过 ws-lab-02 的 QA 遥测任务被证实属于共享托管基础设施，这一事实削弱了对候选事件 evt-810 和 evt-813 的贬义性判断，因为 ws-eng-05 和 ws-eng-09 对该 IP 的访问可能只是接触到同一托管平台的其他租户服务，而非专用 C2 设施。

未闭合缺口集中体现在“候选事件验证未完成”和“host 侧执行链不完整”两大方面。目前仍有至少四条关联事件尚未独立验证，特别是 ws-eng-09 上涉及 cdn-notify-edge.net 和 198.51.100.44 的网络行为，无法确定其是否同样命中本地 JA4 指纹或外部情报，亦无法排除为共享基础设施误碰或正常工具，这意味着当前事件范围在覆盖 ws-eng-09 时存在明显不确定性。另外，ws-eng-09 的 EDR 进程遥测降级已形成明确 telemetry-gap，导致攻击者在第三台主机上能否真正执行载荷、建立持久化或继续横向移动均无法判断。这些缺口虽然不否定现有的已确认主链，但严格限制了将事件定性为“完整攻击链闭环”或“已确认三次横向传播”等更强主张。
