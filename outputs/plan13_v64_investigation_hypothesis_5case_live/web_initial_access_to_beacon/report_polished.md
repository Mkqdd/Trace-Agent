## 1. 事件结论与当前判断

本次事件已构成确认安全事件，分析窗口覆盖 2026-05-11 14:02:00 UTC 至 2026-05-11 14:31:30 UTC。种子告警来自 web-app-01（10.60.1.14）在 14:12:00 UTC 触发的 TLS beacon 检测，命中了 JA4 指纹 t13d1517h2_91adbe210bc1_7cae1281e991，告警情报标注为“Confirmed web initial access to beacon chain”。围绕该告警展开的时间线回溯和扩线检索共汇聚 9 条偏可疑事件，构成了从初始入侵、Webshell 投放、PowerShell 启动器执行、凭据访问到横向移动的一致攻击链。

## 3. 关键证据判断

本次事件的主证据链具备从初始入侵到横向移动外联的完整叙事连贯性，整体研判把握为高。核心支撑来自 web-app-01 上按时间顺序展开的五组确认事实：面向公网登录端点的漏洞利用请求（14:02:00 UTC）、Webshell 文件 shell.aspx 落地（14:16:30 UTC）、PowerShell 启动器在 w3wp 下的执行（14:18:10 UTC）、Web 工作进程账户对凭据存储的访问（14:21:00 UTC），以及 web-app-01 向 app-db-01 发起 SMB 连接（14:24:20 UTC）。这五组事实在约 22 分钟内紧密衔接，且每一步的输出都构成下一步的前提，逻辑上可推导出攻击者获得 Web 入口、部署 Webshell、获取代码执行、窃取凭据并横向渗透的完整攻击链。

外联行为在本案中扮演了辅助锚定角色。web-app-01 在 14:07:30 UTC 解析 cdn-auth-check.net、14:12:00 UTC 触发种子 JA4 beacon 告警并在 14:14:10 UTC 重连同一外部基础设施，三组网络证据将主机侧行为与外部 C2 节点牢牢绑定。更关键的是，app-db-01 在横向移动信号之后于 14:31:30 UTC 主动外联 cdn-auth-check.net 和 198.51.100.88，将横向移动终点与同一 C2 基础设施连通，消除了该通信可能归属正常业务的疑虑。这两组外联闭环保守地将受影响范围限定在 web-app-01 和 app-db-01 两台主机，并为封禁外部基础设施提供了明确指标。

尽管如此，仍未获得支撑更强结论的关键证据。目前没有命令行历史、落地文件完整路径、父子进程树或内存取证结果来确认 PowerShell 启动器的具体载荷内容和执行结果。凭据访问告警虽已触发，但缺少凭据是否成功导出、密码哈希或明文凭据是否落地的直接证据。横向移动仅观测到 SMB 连接和 app-db-01 的后续 DNS 解析与外联，无法确认攻击者是否在 app-db-01 上成功执行了后续载荷或建立了持久化机制。已闭合的缺口（如 minimum context build、asset identification、initial candidate validation）仅表明主链构建条件满足，上述更深层的执行链缺口仍然限制我们断言攻击者完全控制 app-db-01 或完成数据外传。

## 4. 影响范围、候选对象与外部基础设施

已确认受影响资产为 web-app-01 和 app-db-01。web-app-01 作为种子告警的落点主机，承担了初始入侵入口、Webshell 托管、C2 beacon 通信源以及横向移动跳板的角色，其受损程度最深，覆盖了从外部威胁暴露到内网渗透扩散的关键节点。app-db-01 虽然在横向移动前没有独立的入侵迹象，但在 SMB 连接之后出现了与同一 C2 基础设施 cdn-auth-check.net 和 198.51.100.88 的主动外联，且该外联时点紧接横向移动信号之后。这两组事实使 app-db-01 在事件链中处于后端受害节点的位置，应予纳入确认受影响范围，进行隔离和取证。web-app-01 上观测到的漏洞利用、Webshell 落地、PowerShell 执行和凭据访问都统一指向内网 IP 10.60.1.14，该地址作为贯穿事件的时间线锚点，应纳入排查以确认其是否为攻击者初始跳板或仅是 NAT/代理出口。

候选扩线对象包括内部 IP 10.60.2.34 和 JA4 指纹 t13d1517h2_91adbe210bc1_7cae1281e991 的更大范围复现。10.60.2.34 作为 app-db-01 的主机地址，已在主链中作为横向移动目的端出现，但其是否承载了更广泛的后继横向移动或持久化行为仍属待验证候选线索。JA4 指纹已由种子告警明确命中，若在同时间窗内回溯到该指纹在其他内网主机上的命中，可能表明同一工具链在更大范围内使用，当前应将此指纹作为内部网络流量回溯的 关键关联指标，但不等于已确认其他资产受影响。

核心外部基础设施为域名 cdn-auth-check.net 和 IP 198.51.100.88，两者以绑定形式贯穿主链：web-app-01 的 TLS beacon（14:12:00 UTC）、后续重连（14:14:10 UTC），以及 app-db-01 的外联（14:31:30 UTC）均以这对域名和 IP 为目标。此外，app-db-01 在 14:27:00 UTC 单独解析 cdn-auth-check.net 的行为目前为候选事件。这些外部资源只能作为外联对象和关联基础设施对待，应在边界设备上执行封禁和日志回溯。事件中不存在将外部 IP 或域名认定为受影响资产的证据，它们一律属于攻击者控制或利用的外部节点，对应的处置是排查和封禁，而非隔离取证。

## 5. 反证、替代解释与未闭合缺口

本事件中存在一条明确的背景或替代解释：14:04:40 UTC，WAF 遥测显示来自同一源地址 10.60.1.14 的通用扫描器载荷被阻断。该事件与主链在时间上相邻，且均指向 web-app-01，有可能暗示部分甚至全部异常流量来自自动化扫描器而非定向攻击。然而，扫描器载荷被阻断与后续 Webshell 落地、PowerShell 执行之间存在数分钟的间隔，且扫描器不会主动解析罕见 C2 域名或维持 TLS beacon 连接。因此该反证只能收窄我们对初始告警来源的解读，不足以推翻主证据链所建立的入侵和横向移动结论。

另一组边界信号来自 evt-310，即 app-db-01 在 14:27:00 UTC 解析 cdn-auth-check.net 的 DNS 查询。该事件已完成本地情报 ground，但未命中独立外部情报支持，因此当前处于候选状态。如果该 DNS 查询最终被证实属于正常解析缓存、维护工具或共享 DNS 基础设施的副作用，则 app-db-01 与 C2 域名的关联将弱化，但 app-db-01 在 14:31:30 UTC 的主动 TCP 外联仍独立锚定其与外部基础设施的连接。换言之，即使 evt-310 最终被排除，app-db-01 的受影响认定不会因此被否定，只是损失了一条辅助时序参照。

未闭合缺口仍然限制我们做出更强结论。当前缺少 host-side 的命令行历史、落地文件完整路径和内存取证来确认 PowerShell 执行的具体载荷功能和执行完整性。凭据访问告警之后没有观察到凭据转储文件、LSASS 访问记录或后续使用被盗凭据进行认证的日志，因此不能断言凭据已成功泄露。横向移动的 SMB 连接虽然存在，但 app-db-01 上是否执行了后续载荷、是否建立了持久化、是否有数据回传均无直接证据。此外，关于 seed 家族提示“Confirmed web initial access to beacon chain”的外部技术背景未做充分调研，不能排除该提示是对一类通用 Webshell beacon 的泛化标注。这些缺口叠加后形成了一条明确边界：当前可确认事件发生，但不应声称已观察到实现 app-db-01 的完全控制、持久化驻留或数据外泄闭环。

- **立即隔离 web-app-01 和 app-db-01**：在主机层面断开网络连接，保留内存和磁盘镜像用于后续取证，日志源包括 EDR 终端日志、Sysmon 事件、PowerShell 模块日志及 Windows 安全事件日志，验证目标为确认完整的执行链、落地文件清单及凭据访问结果。
- **在边界和代理设备上封禁外部基础设施**：对象为 198.51.100.88 和 cdn-auth-check.net，排查范围覆盖防火墙、Web 代理、DNS 解析器及 NAC 设备，日志源包括防火墙阻断日志、代理访问日志和 DNS 查询日志，验证目标为阻断所有现存及未来外联尝试，并回溯同时间窗内是否存在其他内网主机与这些指标的历史通信。

- **对 app-db-01（10.60.2.34）启动主机取证**：重点关注横向移动后的进程创建、服务安装、计划任务注册和网络连接日志，日志源包括 Windows Event ID 4688、4697、5156 及 Sysmon Event ID 1、3、11，验证目标为确认是否发生了后续载荷执行、持久化或数据回传。
