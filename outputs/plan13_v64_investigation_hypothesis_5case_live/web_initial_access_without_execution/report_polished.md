## 1. 事件结论与当前判断
本次调查围绕 web-app-02 告警展开，种子告警在 2026-06-24 15:02:00 UTC 匹配到一条 Possible web beacon without host corroboration 信标，目标地址为 198.51.100.177，通信使用 TLS 且命中特定 JA4 指纹。结合前后事件链，确认 web-app-02 在较短时间内依次经历了面向管理端口的漏洞利用请求、域名解析 auth-edge-panel.net、基于该域名的信标通信以及后续对同一外部基础设施的再次连接，这一系列行为构成了可疑事件簇的核心主线。当前判断为“可疑事件，建议继续复核”，而非已闭环的攻击成功或恶意软件扩散事件。主要制约在于：主机执行层面仍存在关键缺口，脚本日志未启用导致无法深入验证命令与载荷落地情况，且关联资产 web-app-05 等仍处于待确认状态，需要人工和工具进一步补全证据。

## 2. 事件过程与关键时间线
围绕 web-app-02 的可疑行为集中在 2026-06-24 14:50:00 UTC 至 2026-06-24 15:06:40 UTC 之间。起始事件为 14:50:00，对外服务的 web-app-02 收到面向管理端口的利用请求，源地址为 10.61.2.20；随后在 14:54:00 出现第二波管理端口利用请求，据观测使用了不同的源 ASN 和载荷家族。紧接着，在 14:58:30，该服务器对 auth-edge-panel.net 发起域名解析，将外部通信目标从随机访问转向特定域名的解析与连接准备。分析窗口内最关键的信号出现在 15:02:00，web-app-02 与 auth-edge-panel.net 解析后的 IP 198.51.100.177 建立 TLS 会话，种子告警认定为 Possible web beacon without host corroboration，也就是可能存在 Web Shell 类型的远程信标。该连接发生在利用请求进入后的时间窗口内，且并未随利用请求停止而结束。在 15:06:40，同一资产 web-app-02 再次主动连接同一外部基础设施 198.51.100.177，形成一次自然重连，进一步强化了信标类行为的可能性。值得注意的是，这些连接均由内部地址 10.61.2.20 发起，并与 web-app-02 的事件直接关联，而后续在 15:34:00，一条 WAF 更新规则开始拦截针对同一管理端口的重复载荷，时间上出现在首次信标之后。

此外，扩线过程中出现若干候选事件需要后续验证。在 15:10:00 至 15:12:30，web-app-02 解析并连接了与 auth-edge-panel.net 同属一套基础设施的域名 cdn-auth-edge.net，该连接同样指向 198.51.100.177，但因缺少主机端佐证而未能确认为信标，当前仅列为背景或替代线索。在 15:24:20，另一台服务器 web-app-04 通过 scanner-cdn.example 也连至同一 IP 198.51.100.177，初步被标识为扫描器遥测流量，属于共享基础设施背景的可能解释。在 15:30:00 至 15:32:20，资产 web-app-05 对 cdn-auth-edge.net 进行了 DNS 解析和短 TLS 连接，但其本地并无匹配告警，因此只能作为待确认的候选范围，尚不能认定为受影响资产。

## 3. 关键证据判断
当前已确认的可疑事件主线建立在时间线上高度连续的五个关键事实上：利用请求进入、对 auth-edge-panel.net 的域名解析、种子信标告警触发、以及随后的重连全都集中在约 16 分钟的时间窗口内，且均围绕同一资产 web-app-02 与同一外部基础设施 198.51.100.177 和域名 auth-edge-panel.net。这一序列在逻辑上符合“利用→解析→信标→复连”的行为模型，不存在明显交叉矛盾。种子告警携带的 JA4 指纹为 t13d1517h2_22adbe210bc1_11cae1281e22，该指纹在信标 TLS 会话中出现，为主链提供了可追溯的通信特征。信标发生前连续出现的两种管理端口利用请求增强了 web-app-02 对外暴露面受到主动探测和利用尝试的研判基础，而非单纯的背景流量。事件在时间与对象层面高度聚焦，没有漂移到无关资产。

然而，当前证据无法支撑更强的结论，例如攻击者获得主机执行控制、完整的可疑执行活动链、持久化驻留或跨主机横向移动。主要原因在于 web-app-02 的主机侧遥测存在明显缺口：脚本日志未启用，导致无法获取命令行与进程落地细节；同时主机遥测在分析窗口内未观察到 Web 工作进程产生可疑的子进程活动，这表明即使可疑行为聚焦于服务层，仍缺少确凿的在主机上执行后续恶意负载的证据。当前结论虽然可以交付为“可疑事件簇”，但无法直接认定为“已确认安全事件”或“已观察到获取控制权”。种子告警所附带的家族提示也明确标注为“without host corroboration”，这类提示本身就是局限性表述，提醒研判者必须在缺乏主机佐证的条件下谨慎使用。任何进一步扩线都需要补充主机执行层面和更大范围关联告警的证据，否则攻击闭环只能作为假设存在。

## 4. 影响范围、候选对象与外部基础设施
基于主链证据，已经纳入确认受影响范围的是资产 web-app-02，它出现在全部五条主线事件中，无论是被利用的对象、发起解析的节点还是信标外联的源端，均指向同一资产及其对应内网地址 10.61.2.20。web-app-02 在该事件中的行为已足够特定，将其列为需要深入隔离和取证的对象是当前分析的主干结论。

同时也存在一批候选对象和关联基础设施，需要后续独立核查才能扩大影响范围。资产 web-app-05 在 15:30:00 后对域名 cdn-auth-edge.net 进行过 DNS 解析，并在 15:32:20 连接到同一外部 IP 198.51.100.177，但其通信没有伴随特指信标告警，因此目前只能列为待确认候选对象，不能直接认定其真实受到影响或有恶意行为执行。类似地，资产 web-app-04 通过 scanner-cdn.example 连接至 198.51.100.177 的流量目前被倾向解释为扫描器遥测或共享托管背景事件，不应错误列为已受影响资产。

核心外部基础设施集中在域名 auth-edge-panel.net 和 IP 地址 198.51.100.177，二者是主链中信标交互的直接指向对象。cdn-auth-edge.net 和 scanner-cdn.example 则是与主域名共享同一托管 IP 的域名，前者在主资产上出现了无佐证连接，后者在其他资产上出现，两者均为需要纳入排查与封禁范围的外部对象，但不代表它们本身就是攻击者独有的基础设施。外部 IP 与域名如需上线封禁，必须配合威胁情报或其他外部佐证进一步确认。

## 5. 反证、替代解释与未闭合缺口
多条背景事件和候选反证限制了在不补充新证据的情况下做出更强判断。一是同一分析窗口内，web-app-02 存在计划内的管理端口补丁部署记录，在 15:18:00 观察到的维护行为有可能使得利用请求的来源和时点存在业务活动的噪音干扰。这并不意味着本次利用请求就是补丁操作本身，但说明无法完全排除维护窗口期间异常行为与业务变更存在部分重合的可能。二是主机遥测在窗口内未观察到 web-app-02 上来自 Web Worker 的异常子进程活动，这与一般情形下攻击者在 Web 服务器上完成信标后会执行后续命令或下载载荷的预期不一致，因此主机侧行踪缺失构成当前最核心的反证。三是 web-app-04 通过 scanner-cdn.example 到达同一托管 IP 的流量，以及 web-app-05 对 cdn-auth-edge.net 的低强度 TLS 连接，均存在共享基础设施或扫描器遥测这类良性解释，一旦 198.51.100.177 被确认为 CDN 或多租户基础设施，部分流量的恶意性将需要重新评估。

此外，报告存在若干未闭合缺口，这些缺口限定了当前结论的上限。最大的缺口仍是主机执行链缺失，即未找到命令执行、持久化方法落地和跨主机扩线证据，这对从“可疑外联”上升到“已确认安全事件”构成直接阻碍。另一缺口是需要对 web-app-05 进行独立复核，确认其行为是共享基础设施背景还是真实受影响对象，当前分析只能扩展候选范围而不能做出倾向性结论。更广泛层面，需要在更宽时间窗口内围绕同域名、同 IP 和同 JA4 指纹进行扩线搜索，以确认是否存在其它复现资产。种子告警携带的家族提示本身仅是一个起点，需要外部威胁情报或公开技术资料补充其背景与可信度。反证与缺口共同指向一个结论：当前主链成立，但在未闭合这些问题之前，不能宣布事件范围已划定或漏报已排除。
