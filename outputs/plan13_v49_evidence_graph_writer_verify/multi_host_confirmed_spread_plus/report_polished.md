- **一句话结论：** 种子资产 `ws-eng-02` 与第二个资产 `ws-eng-05` 先后与同一 C2 基础设施通信，其间出现 PsExec 远程服务创建及二次外联，构成多主机信标扩散事件

## 1. 事件结论与当前判断

经多轮证据扩线与反证检查，本次告警已确认为一次高风险的多主机信标扩散事件。种子告警 `Suspected multi-host beacon spread` 命中 JA4 指纹 `t13d1516h2_2ba4190accc0_13fe129f5abc`，该指纹被确认为此次受控通信的关键通信特征。事件主线覆盖内网两台主机 `ws-eng-02` 与 `ws-eng-05`，它们先后与同一组外部基础设施 `sync-cdn-notify.net` 和 `203.0.113.77` 建立 TLS 可疑连接，信标行为具备明显的重复性与时序关联。分析窗口为 2026-07-14 01:04:00 UTC 至 2026-07-14 01:49:00 UTC，在该时间段内，从种子资产到第二资产的信标扩散证据链基本闭合，主链事实的可信度足以支撑事件级交付。

尽管本次研判达到了确认事件的门槛，但仍存在一些未闭合的证据缺口，限制了更强结论的推导。当前，ws-eng-02 上的可疑执行线索（如 rundll32 加载可写路径下的 DLL）缺少完整的命令行与持久化证据；横向移动步骤的远程服务创建与后续信标的衔接虽存在，但尚未完成主机侧取证闭环。因此，现阶段将事件定性为“多主机信标扩散”，而非“攻击者完全控制链路闭环”。这些边界将在第 5 节中详细阐述。综合主证据强度与剩余缺口，将该事件对业务资产安全构成的威胁等级评定为高危，处置优先级最高。

## 2. 事件过程与关键时间线

事件始于 2026-07-14 01:04:00 UTC。此时，种子资产 `ws-eng-02` 的源地址 `10.70.3.12` 进行了一次罕见的 DNS 解析，查询域名为 `sync-cdn-notify.net`。这一解析紧随其后，在 01:10:00 UTC，告警系统在同一资产上捕获到一个具备特定 JA4 指纹 `t13d1516h2_2ba4190accc0_13fe129f5abc` 的可疑 TLS 信标，目标同样指向 `sync-cdn-notify.net` 对应的基础设施 IP `203.0.113.77`。告警将此次通信标记为“Suspected multi-host beacon spread”，成为整个事件链的核心锚点。

随后，信标通信并未停滞。在 01:14:20 UTC，`ws-eng-02` 再次与同一对 C2 目标（域名 `sync-cdn-notify.net`，IP `203.0.113.77`）建立连接，表明其并非一次短促的连接尝试，而是存在持续受控指令交互的可能。事件在 01:18:00 UTC 进一步升级，`ws-eng-02` 上出现了可疑进程执行活动：系统通过 rundll32.exe 从一个用户可写路径加载了 DLL 文件，这一行为在信标序列之后出现，具备高度威胁叠加特征。到 01:21:10 UTC，`ws-eng-02` 发起了一次明确的横向移动尝试，通过 PsExec 向另一台内网主机 `10.70.3.45`（即 `ws-eng-05`）创建远程服务，其时间点紧贴信标通信，将此前的网络行为和主机行为串联起来，形成了潜在的“感染-信标-横向移动”攻击链。

事件范围自此明显扩展。仅在七分钟后，即 01:28:40 UTC，第二台内网资产 `ws-eng-05`（源地址 `10.70.3.45`）的日志显示，它已经主动向原始的 C2 基础设施 `sync-cdn-notify.net` 与 `203.0.113.77` 发起了 TLS 连接。这表明信标已经扩散到了第二个受害者。在此之后，监控系统还捕获了一些需要独立验证的候选扩展事件：`ws-eng-05` 在 01:32:10 和 01:36:00 UTC 先后解析并连接了一个新的罕见域名 `cdn-notify-edge.net` 及关联新 IP `198.51.100.44`。这些活动潜在地指向攻击者正将通信迁移到备用 C2 设施，但其具体指令与产生的上下文对于当下仍属于待验证范围，不应直接计入已落实的损伤范围。

## 3. 关键证据判断

在当前证据网中，支撑事件成立的核心判断来源于两组一致性极强的已确认事实。首先，关于多主机信标扩散的结论，其主支撑在于 JA4 指纹 `t13d1516h2_2ba4190accc0_13fe129f5abc` 与 C2 基础设施在先后端口上的关联重复性。从 `ws-eng-02` 的信标触发（evt-802），到该资产的后续连接（evt-803），再到 `ws-eng-05` 主动外联同一组 C2 的信标行为（evt-808），在此重复过程中，域名 `sync-cdn-notify.net` 和 IP `203.0.113.77` 是稳固不变的聚焦点。这种在不同主机、相异时间、同一组网络目标上重复出现的通信行为，本身就排除了单点误报或偶然信息系统的可能性，构成了非孤立、可迁移的事件簇。另一方面，本地情报库针对 `sync-cdn-notify.net` 与 `203.0.113.77` 查询时未返回已知恶意家族记录，这虽然表明这些基础设施可能是攻击者的新设施，但并不削弱其在此次事件中作为已确认 C2 通道的实质判断。事件中观察到的横向移动行为，即 PsExec 远程服务创建（evt-805），与信标的扩散在时序上高度贴合，进一步提高了已确认主链证据的解释一致性。

尽管如此，当前未闭合的缺口也精确限制了结论的高度。截至目前，ws-eng-05 的信标行为过程缺少底层进程执行树状证据的确证。例如，尽管我们在 ws-eng-02 上看到了悬疑执行线索，但在第二台资产 ws-eng-09 上，由于 EDR 传感器报告了进程遥测降级（evt-814），无法重建其信标链背后的执行谱系。同时，“候选事件尚未独立验证”是本次研判中的一项核心缺口。围绕 evt-809 到 evt-814，以及候选域名 `cdn-notify-edge.net` 和 IP `198.51.100.44` 的记录，虽然暗示了攻击设施切换和新资产蔓延的可能性，但因为这些候选事件未与独立于本次告警的外部威胁情报、本地主机执行日志或确定的持久化证据形成闭环，目前它们仅能作为边界线索存在，不能成为我们主张“已观察到完成对更多资产的完全控制”这一更强结论的基础。证据能力已经足以交付当前确定的“多主机信标扩散事件”，但继续推导出横向移动闭环或持久的遥测接管，则需要后续现场取证填补这些明确指出的缺口。

## 4. 影响范围、候选对象与外部基础设施

基于线上主证据链，率先需要纳入确认受影响范围的内部资产为 `ws-eng-02`（源地址 10.70.3.12）和 `ws-eng-05`（源地址 10.70.3.45）。`ws-eng-02` 是种子报警的承载者，在该主机上已发生多轮指向外部 C2 的可疑信标通信，以及显著的信标关联后进程执行和横向移动痕迹。`ws-eng-05` 的主机则被观测到直接与原始信标 C2 设施进行了通信，确认受到信标扩散。在逻辑上，`ws-eng-05` 已经成为了攻击者可能进一步操控或从其上发起跳板访问的节点，因此这两台主机都是隔离和应急取证的首要对象。对于环境内其他候选资产，比如出现在边界线索中且涉及横向移动告警的 `ws-eng-09`（关联源 IP 10.70.3.90），以及仅在背景解释流中接触过共享基础设施的 `ws-lab-02`（源 IP 10.70.8.22），当前均不能被编辑入已确认影响面。`ws-eng-09` 和相关的指向必须定位为待核查扩线资产进行额外验证。

就外部关联点而言，核心事件中反复作为连接目标的外部对象是域名 `sync-cdn-notify.net` 与 IP `203.0.113.77`，它们是此次多主机信标通信的核心外部基础设施。鉴于在信标及横向移动的关联中该组对象被反复命中，该域名和 IP 应当作为高优先级封禁对象进行边界策略阻断和潜在历史通联排查。另一组值得注意的对象是候选事件浮现的域名 `cdn-notify-edge.net` 和所解析到的 IP `198.51.100.44`。业务日志显示，之后有完全不同的QA遥测任务（ws-lab-02 至 `telemetry-collector.example`）也连接到了同一个后端 IP `198.51.100.44`，这给后者打上了“共享基础设施”的背景标签。然而这种背景信息是将 `cdn-notify-edge.net` 和 `198.51.100.44` 当作需要密切监控的关联基础设施的信号，在排查中封禁该 IP 或域名前，必须先完整确认其对安全域内其他合法业务的影响面。所有待确认的外部线索域，包括 `cdn-notify-edge.net`，目前均只视为候选外联目标，与已确认需立即强硬封禁的 `sync-cdn-notify.net` 和 `203.0.113.77` 完全不同。

## 5. 反证、替代解释与未闭合缺口

在此次研判过程中，我们明确寻找了能够提供良性解释的边界证据。数据表明，介于 2026-07-14 01:24:00 UTC 和 01:26:00 UTC 的时间窗，横向移动目标 `ws-eng-05` 上出现了 SCCM 补丁暂存（evt-806）和一条指向微软官方 Windows 更新 IP `13.107.246.45` 及域名 `download.windowsupdate.com` 的良性下载记录（evt-807）。这两项背景事件发生在信标扩散链条中 ws-eng-05 的横向移动指向与信标出现之间，表明在该主机上，受到认可的内部管理操作（补丁与维护）窗口与可疑行为在时间线上共存。由于这种维护通信可以在特定环节产生正常的管理员级远程交互，它们为 ws-eng-05 上局部活动的解释提供了噪声来源，但其解释力仅限于局部活动的收窄边界。因为针对同一资产 ws-eng-05，我们同步拥有其对原始 C2 目标特定通信的确凿重复信标证据，且该信标所涉及的 `sync-cdn-notify.net` 流量不具备任何公司已知的更新或补丁下发特征，故维护背景无法否决 ws-eng-05 被信标投递收拢到 C2 频道内这一核心问题。

此外，与候选线索相关的共享基础设施发现进一步限制了影响范围的过度扩展。在后续时间点，来自环境内常规 QA 实验室的资产 `ws-lab-02` 确实连接了 `198.51.100.44` 上的 `telemetry-collector.example`，这充分说明 `198.51.100.44` 是一片共享的外部服务托管地址，它并不仅服务于本事件中出现的可疑二级活动。鉴于候选事件 evt-810 和 evt-813 也将其流量指向了同一 IP `198.51.100.44`，共享性质直接否定了我们当下将这些候选流量纯粹定义为“攻击者专有备用设施”的能力。事件中最关键、最能制约更强结论推演的未闭合缺口，是扩线得到的多项关联事件始终未获得独立验证。除了安全信息层面缺失外部情报命中外，ws-eng-09 上的 EDR 遥测丢失（evt-814）使端侧杀伤链在候选主机上断裂，而 evt-811 的 WMI 远程执行候选事件同样缺失可独立验证的落地文件或命令行凭证。这些现象共同构成了一堵壁垒，让我们对攻击者是否达成了第三次主机跳跃、是否实现了代码执行延续等问题，必须以严格的事实限制框定在“无法证实”的边界内，不得将视角延伸至事件交付硬事实之上。

## 6. 处置建议与后续核查

- 隔离并重点监控已确认受影响资产：对象为 `ws-eng-02`（10.70.3.12）和 `ws-eng-05`（10.70.3.45）。在这些主机上，使用内置系统工具提取计划任务、服务列表与 AppInit_DLLs，重点检查是否存在与 `rundll32.exe` 联动或可疑 DLL 侧加载的持久化条目。验证目标是确认当前主机无额外加载点及长久驻留程序，并为取证建立基线。

- 排查并针对性封禁核心外部基础设施：通过出口防火墙、安全 Web 网关或代理日志，检索涉及 `sync-cdn-notify.net` 和 `203.0.113.77` 的历史连出记录（字段关注目标域名、目标 IP 及发起源 IP），对仍处于活跃状态的连接立即阻断并禁止新的 DNS 解析，排查是否存在更多未知资产在该时间窗内触达同样的 C2。

- 逐条验证候选扩线事件：针对候选事件 evt-809 到 evt-814、涉及资产 `ws-eng-05` 和 `ws-eng-09` 的活动，重点检索 EDR 日志中的进程链（Process Create）、文件创建事件和网络连接日志，围绕域名 `cdn-notify-edge.net` 及 IP `198.51.100.44` 执行连接关联查询。验证目标是判断这些二级连接是否是新的信标内容、是否伴随主机的文件写入或驻留迹象，从而决策是否将相关资产正式转入已确认受影响范围。

- 提取种子主机上的主机取证证据：使用端点检测工具，拉取 `ws-eng-02` 上对应时间窗口的 `Microsoft-Windows-Sysmon/Operational` 日志，重点关注 EventID 1（进程创建）和 EventID 11（文件创建），定位 rundll32.exe 加载的用户可写路径 DLL 实体，确认其哈希值并查询本地威胁情报，以期揭示恶意 DLL 的初始投递源和功能手段。

- 以核心指标推动主动威胁狩猎：在日志管理平台中以 JA4 指纹 `t13d1516h2_2ba4190accc0_13fe129f5abc`、域名 `sync-cdn-notify.net` 和 IP `203.0.113.77` 为检索关键字，拉取过去 30 天内的时间线，识别是否存在早期、低频的同类信标记录，确保不会遗漏在初始触警前就已开始活动的潜伏控制面。
