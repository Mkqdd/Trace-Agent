## 1. 事件结论与当前判断

种子告警「Suspicious shared-infra beacon requiring review」于 2026-06-20 10:12:00 UTC 触发，命中资产 ws-legal-03 向域名 auth-queue-sync.net（解析至共享托管 IP 198.51.100.131）发起的 TLS 会话，且关联 JA4 指纹 t13d190900_7711aa22bb33_9911ccddee77。围绕该种子，进一步检索到 3 条偏可疑事件，集中在同一域名与 IP 上；同时，在另外两台资产 ws-legal-09 和 ws-legal-12 上也发现了触及相同共享 IP 的弱信号。然而，当前尚不具备主机侧执行、持久化或横向移动的证据，且存在多条可解释为正常业务或共享基础设施的背景事实，因此整体判断仍停留于可疑事件层，建议继续人工复核后再做结论。

## 3. 关键证据判断

种子告警本身并非孤立信号。事实 evt-703 和 evt-704 所呈现的两次重连，分别出现在告警之后的 4 分钟和 9 分钟，连接对象相同且都复用同一 JA4-相邻的共享托管路径，使得异常信标的置信度明显高于单一偶发连接所能支持的水平。特别是，该行为发生在告警已被生成之后，表明外联程序或机制并未因单次被标记而中断，具有某种周期性或续接特征。结合 DNS 解析先序事件 evt-701，可以判断 ws-legal-03 至少在执行一次有明确域名目标的、到 198.51.100.131 的 TLS 通信序列，不同实体之间的时间间隔、域名固定度及 TLS 指纹复用共同构成指向共享基础设施信标的证据链。

然而，主机侧取证视角的空缺严重限制了这一证据链能够推导出的上限结论。在受关注窗口内，ws-legal-03 缺少命令行遥测，无法确认是何种进程发起上述连接、是否伴随脚本或二进制落地、是否有计划任务或其他持久化痕迹。同样，ws-legal-09 在相关时段也没有 EDR 命令行覆盖。因此，即便网络侧已观察到特征明显的 beacon 行为，仍不能将其直接升级为“已确认可疑执行活动”、“载荷完整投递”或“攻击者实现主机控制”。这些缺口迫使当前结论必须停留于“可疑信标活动”层面，仅能确认存在不应忽略的网络异常，而无法对主机侧状态做出任何肯定性声明。

## 4. 影响范围、候选对象与外部基础设施

已确认受影响的内部资产仅限 ws-legal-03，其作为种子资产，在约 10 分钟内三次向外部基础设施发起可疑 TLS 连接，且均被同一 JA4 指纹覆盖。该资产目前已纳入主证据链，属于必须重点排查和取证的对象。外部基础设施方面，198.51.100.131 是整个事件簇中反复出现的核心共享托管 IP，域名 auth-queue-sync.net 则直接与种子告警和重连行为绑定。这两者构成了核心外部基础设施，应在边界与代理侧作为封禁和回溯目标。

候选对象层面，ws-legal-09 和 ws-legal-12 各自通过不同的域名（cdn-auth-queue.net、legal-docs-cdn.example）触碰了相同的共享 IP，但其流量强度极低，且始终缺少重复性连接或主机侧遥测印证。ws-legal-09 同时还用正版 identity-cache.vendor.example 访问同一 IP，进一步体现了该 IP 承载多租户、多 SaaS 的真实共享特征。因此，这两台资产当前仅可视为待确认关联资产，不能直接认定为受影响范围。扩展候选还包括：域名 login-queue-cdn.net 及其解析 IP 203.0.113.131，它们来自 ws-legal-03 的后续一次孤立 DNS 与 TLS 交互，不共享种子 IP，是否需要纳入同一事件仍有待补充情报验证。JA4 指纹 t13d190900_7711aa22bb33_9911ccddee77 同时可作为进一步网络扩线搜索的候选指标，以发现潜在的同特征复现。

## 5. 反证、替代解释与未闭合缺口

事件中出现的多项背景事实，对将网络外联直接定性为攻击性 beacon 构成了有效限制。198.51.100.131 在同一周内曾托管多个无关客户域名的被动基础设施上下文，说明该 IP 本身即属于多租户共享环境，auth-queue-sync.net 的存在并不必然意味着唯一恶意。ws-legal-09 于相近时段通过正版身份缓存域 identity-cache.vendor.example 访问同一 IP，更直接地证明该 IP 与合法 SaaS 业务存在关联。此外，在 ws-legal-03 上，一场已批准的 SSO 浏览器扩展更新恰与首条可疑 TLS 会话时间重叠，且紧随其后出现了正常的 Microsoft 登录流量，构成了“可能因业务更新或 SSO 工作流引发的不常规网络连接”这一替代解释路径。这些事实虽不能单独推翻主链，但合理收窄了直接判定为 C2 信标的信心边界。

未闭合缺口同样明确划定了当前判断的上限。主机侧执行证据的缺失是最关键的制约--缺少命令行、进程树、文件落地与持久化痕迹，意味着无法证明 attack chain 已完成从网络连接向负载执行的跃迁。资产 ws-legal-09 和 ws-legal-12 是否真实受同一事件波及，仍处于完全未知状态。围绕 关键关联指标（域名、IP、JA4）的更大时间窗复现搜索尚未拉开，无法排除是否存在更广泛的“信标集群”。此外，种子提示“Suspicious shared-infra beacon requiring review”本身未被外部情报佐证，其家族属性仍为待验证提示。这些缺口要求后续处置不可跳过人工扩线环节，在解决它们之前，不应将当前事件推进为确认安全事件。
