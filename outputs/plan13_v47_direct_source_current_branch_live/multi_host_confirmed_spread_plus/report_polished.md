## 1. 事件结论与当前判断

## 3. 关键证据判断

事件判定路径主要由一条从时间序列、行为模式到资产关联的证据链推动。种子告警本身并非孤立的信标匹配，而是嵌入在一系列连贯的行为中。第一组决定性支撑来自资产 `ws-eng-02` 在 6 分钟内的连续动作：它先解析了罕见域名 `sync-cdn-notify.net`，随即与之建立被 JA4 指纹标记的 TLS 信标会话，并在告警后重现了相同的外联模式。这种“解析-信标-重连”的时序结构，极大降低了误报可能性，并建立了稳固的 C2 通信行为画像。

紧随其后的两条事实将事件性质从外联升级为入侵和传播。在 2026-07-14 01:18:00 UTC，`ws-eng-02` 上发生的 `rundll32.exe` 从用户可写路径加载 DLL 的行为，直接关联到信标活动之后，构成了从“受控通信”到“载荷执行”的逻辑闭环；尽管缺乏命令行参数以进行更深度的恶意软件分析，但这一可疑执行路径足以支撑主机侧已发生入侵后行为的判断。紧接着，`ws-eng-02` 利用 PsExec 对 `ws-eng-05` 创建的远程服务，则提供了清晰的横向移动机制。而 `ws-eng-05` 在远程服务创建后仅约 7 分钟即复用种子 C2 基础设施（`sync-cdn-notify.net`）的事实，是连接攻击源、横向手段与扩散后果的关键节点，将整个事件从单点告警闭合为一起已扩散的信标传播事件。

事件之所以能被定级为“确认安全事件”，是因为上述事实提供了关于攻击链入口点（C2信标）、驻留/执行动作（可疑加载器）、横向移动（PsExec远程服务）以及横向成果（第二资产回连）的连贯视图。然而，判断的上限同样明确：在缺乏对 `rundll32.exe` 命令行、载体 DLL、持久化机制和内存样本等主机取证数据的独立确认前，我们仅能将其定性为高度可疑的执行链而非已确认的特定可疑加载器；同样，PsExec 和 WMI 事件支撑了横向移动的行为推断，但在目标主机 `ws-eng-05` 和 `ws-eng-09` 上未发现落地文件或后续独立执行证据时，我们不能将此行为描述为“已观察到完全控制”这些资产。

## 4. 影响范围、候选对象与外部基础设施

目前的分析将已确认受影响范围限定在资产 `ws-eng-02` 和 `ws-eng-05` 内。`ws-eng-02` 是整个攻击链条的起点，同时承载了 C2 信标、可疑载荷执行和横向移动的发起动作，因此是首要的受损资产。`ws-eng-05` 在确切的横向移动（来自 `ws-eng-02` 的 PsExec 远程服务创建）后，于 2026-07-14 01:28:40 UTC 独立连接了与种子相同的 C2 服务器，这一行为使 `ws-eng-05` 被纳入已确认受影响资产，需要立即隔离和取证。

事件簇在扩展到第二台资产后，出现了明显的“基础设施切换”迹象，由此衍生出一系列候选对象和待验证的边界。资产 `ws-eng-09` 以及新出现的域名 `cdn-notify-edge.net` 和 IP `198.51.100.44` 共同构成了一条显著的扩线链。具体而言，在 2026-07-14 01:39:20 UTC，尽管 `ws-eng-05` 向 `ws-eng-09` 的 WMI 远程进程创建事件因缺少独立验证指征而被标记为候选，但它为监控新增资产 `ws-eng-09` 的行为提供了直接动机。随后，`ws-eng-09` 自身解析并通信至 `cdn-notify-edge.net` 的行为，强化了该资产可能已成为新一轮扩散跳板的疑虑，但其状态必须严格限定为“待确认关联资产”，在取得独立的执行证据或信标命中确认前，不能将其并入已确认影响范围。

外部基础设施的界定同样是主证据链与边界信息并存。核心外部基础设施是 `203.0.113.77` 及其关联域名 `sync-cdn-notify.net`，它们是主证据链中反复出现的关键外联目标，应作为首要的封禁和排查对象。对于二次出现的外部基础设施 `198.51.100.44` 和 `cdn-notify-edge.net`，其角色则更为复杂：一方面它们是攻击者可能在扩散后启用的新 C2，因此是关键的扩线候选指标；另一方面，背景事实明确指出资产 `ws-lab-02` 上运行的 QA 遥测任务也通过无关域名 `telemetry-collector.example` 与同一 IP `198.51.100.44` 通信，有力证明了该 IP 属于共享基础设施。这虽然不能否定其作为可疑 C2 的可能性，但极大地限制了我们将其直接定性为专有关联外部基础设施的把握，必须结合更精确的路径、URI 模式或 JA4 指纹进行区分排查。

## 5. 反证、替代解释与未闭合缺口

存在一组有力的反证与替代解释，主要围绕 `ws-eng-05` 资产上的活动及其后续的边界事件展开，它们直接限制了我们得出更扩展到结论的能力。在 `ws-eng-05` 被确认与 C2 通信的前后，同一资产于 2026-07-14 01:24:00 UTC 开始了经批准的 SCCM 补丁暂存活动，并在随后（2026-07-14 01:26:00 UTC）从经验证的微软端点 `download.windowsupdate.com` 下载更新内容。这揭示了一个高度重叠的维护窗口。这一背景虽不能直接否定捕获到的信标行为是恶意的，但它意味着 `ws-eng-05` 上在此期间的任何系统进程、网络连接或服务操作都可能混杂着正常的 IT 管理活动，这足以削弱对“所有 PsExec 和 WMI 远程活动一概归因于攻击者”这一更强结论的信心。

另一组关键限制因素来自于第二跳基础设施的归属模糊性。`ws-eng-05` 后续转向 `cdn-notify-edge.net` 及其解析 IP `198.51.100.44` 的行为，是扩线推论的核心。然而，除上述 WMI 候选事件缺乏独立证据外，攻击链的延伸在逻辑上遭遇了一个明确的共享基础设施反证：在 2026-07-14 01:46:20 UTC，网段截然不同的资产 `ws-lab-02` 通过良性域 `telemetry-collector.example` 也连接到了 `198.51.100.44`。这一事实导致 `198.51.100.44` 不再能被视为可疑 C2 的唯一标识。这也正是候选事件 evt-810 和 evt-813（围绕 `cdn-notify-edge.net` 的通信）尽管已完成本地情报验证，但仍不能直接并入主证据链的根本原因。我们视其为高价值边界线索，但需在排除其共享托管业务后，才能作为支撑更广范围传播的证据。

报告当前识别并保留了若干未闭合缺口，这些限制着案例的最终定级和处置广度。首先，对维护窗口、补丁和共享基线等反证的检查仍属显式缺口，需要系统地收集 ws-eng-05 在事发时段的补丁日志、任务计划及与 SCCM 服务器的管理连接记录，以评估可疑活动与正常运维的交叠程度。其次，来自 `cdn-notify-edge.net` 和 `198.51.100.44` 链的 2 条关键关联事件尚未完成独立验证，未能判定是否应并入主事件范围，这直接形成了攻击活动是止步于 `ws-eng-05`，还是已经蔓延至 `ws-eng-09` 乃至其他资产的关键认知缺口。此外，关于 seed 告警携带的家族提示“Suspected multi-host beacon spread”及特定 JA4 指纹，尚未补充公开技术背景调查，导致我们当前对攻击者工具集的认知仅停留在行为层面，缺乏对攻击团伙或工具家族的外部情报关联，这限制了归因和基于情报的全面狩猎能力。
