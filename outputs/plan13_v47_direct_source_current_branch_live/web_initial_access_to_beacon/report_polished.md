## 3. 关键证据判断

种子告警 JA4 指纹匹配是整个事件的锚点，它将前期漏洞利用和域名解析从孤立异常串联为攻击链入口。`t13d1517h2_91adbe210bc1_7cae1281e991` 这一指纹并非普通的客户端 TLS 指纹，而是外部情报中明确与 Web Shell 信标行为绑定的特征。同一指纹在告警窗口内的持续外联（14:14:10 UTC 的再次连接）排除了单次误触发的可能，也为后续文件落地提供了清晰的 C2 意图解释。

文件 `shell.aspx` 出现在 `/var/www/html/.cache` 这一行为是链式时间序列中的关键物证。它在漏洞请求之后、C2 外联峰值期内出现，并在随后被 PowerShell 启动器引用，形成“漏洞-后门-执行”的三段闭环。这条证据链不需要攻击者真实载荷的完整还原，即可推定已观察到获得在 Web 服务器上下文内运行代码的能力。紧接着的凭据存储访问使事件性质从“Web 入口获得代码执行”升级为“可能已发生凭据泄露”，显著加重了横向移动的风险评估。

SMB 连接与后续 `app-db-01` 独立外联是当前横向推进判断中最有力的两条线索。`web-app-01` 在 14:24:20 UTC 启动内网 SMB 连接，方向指向数据库节点；7 分钟后 `app-db-01` 自行向同一外部 IP/域名发起流量，而非单纯响应 `web-app-01` 的转发。这种“发起方-目标先后独立信标”的模式，使得单纯的内部资产误用或扫描器行为的替代解释大幅降低，转而支持“已观察到 `app-db-01` 上植入了同类信标机制”的判断。该判断虽然因缺少该节点上独立的文件落地或进程证据而尚未完成终极闭合，但联合 DNS、流记录和远程服务创建信号，已将 `app-db-01` 可靠地纳入已确认受影响范围。

相比之下，远程服务创建事件 evt-312 虽发生合理，但因后续分析确认其缺少可独立验证的指示物（如服务名、启动类型、注册表项或相关日志），当前仅作为边界线索保留，未用于进一步升级“已观察到完全控制 `app-db-01`”或“横向移动已完成至最终持久化”的结论。同样，`app-db-01` 对 `cdn-auth-check.net` 的 DNS 解析（evt-310）因仅完成本地情报 grounding 而未命中外部独立情报，也只能作为辅助佐证，不独立作为 C2 信道建立的确认证据。这些约束使我们在确认影响范围时能够保持必要的保守，但仍确保已确认资产符合主证据链的支撑强度。

## 5. 反证、替代解释与未闭合缺口

事件窗口内存在一系列背景事件，它们不能单独推翻主链，但限制了某些更强结论的得出。同一窗口初期，WAF 遥测显示 `web-app-01` 曾遭通用扫描器载荷攻击并被屏蔽，这提示最初的外部探测可能包含自动化扫描背景，但并不削弱后续成功利用和信标建立的事实，因为漏洞利用请求与后续确定的 C2 行为在时间与资产上高度耦合，远超出普通扫描器的行为范围。在 `web-app-01` 上，14:50:00 UTC 启动的计划内热修复部署可能解释了后期服务重启行为，这意味着我们不能将窗口后段的所有服务状态变更直接归因于攻击者，对持久化机制和重启后信标活跃度的解释必须结合这一维护窗口做区分，否则可能高估攻击者的操纵深度。

`app-db-01` 在 14:27:00 UTC 对 `cdn-auth-check.net` 的 DNS 解析虽在时间上与 SMB 连接贴合，但其本身被归类为背景/替代解释事件，原因是它暂未命中独立情报印证，可能受到内部 DNS 转发或 Web 代理缓存的影响，因而不能作为独立的“C2 信道已建立”的唯一依据。我们将其结合后续 `app-db-01` 主动流连接（14:31:30 UTC）和远程服务创建信号后综合使用，而不是单独依赖它得出“已感染”结论。

未闭合的缺口决定了当前判断的上限。首先，`web-app-01` 上的 PowerShell 启动器虽已确认，但由于同一主机上脚本块日志被禁用（候选事件 evt-316），导致完整命令行和加载模块细节缺失，限制了对攻击者载荷功能（信息收集、持久化、凭证转储等）的完整还原。其次，`web-app-01` 到 `app-db-01` 的远程服务创建缺乏可独立验证的指示物，使得横向移动的最终落实情况（服务是否成功启动、载荷是否在目标上执行）仍待确认。围绕 `cdn-auth-check.net`、`198.51.100.88` 等指标扩线到的关联事件尚未完全独立验证，至少有一条关联事件仍未融入主链，无法排除是否存在更大的影响半径。种子家族提示 `Confirmed web initial access` 也缺乏进一步外部技术情报的上下文填充，目前只能作为行为模式标签使用，不能支撑详细的 TTP 归因。此外，尚未系统性检查维护窗口、补丁、备份等基线活动对事件信号的干扰程度，该缺口的填补将直接影响对部分行为（如服务重启、进程创建）是否与攻击相关的最终定论。

这些缺口不会降低已确认结论的可信度，但明确划定了当前应停止推测的边界：在主机侧取证闭合、候选事件验证完成并排除维护窗口影响之前，不宜将结论升级为“已观察到多台主机上实现完全控制并建立持久化”。
