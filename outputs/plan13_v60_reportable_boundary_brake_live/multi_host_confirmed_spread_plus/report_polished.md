## 1. 事件结论与当前判断

本次分析基于 2026-07-14 01:04:00 至 01:39:20 UTC 期间的事件簇，最终交付结论为“确认安全事件”。种子告警（JA4 指纹 t13d1516h2_2ba4190accc0_13fe129f5abc 命中）指出 ws-eng-02 存在“Suspected multi-host beacon spread”，该提示贯穿整个调查，并与随后陆续发现的可疑 DNS 解析、进程执行与远程服务创建行为形成一致的方向。当前确认的主证据链由两条已闭合执行缺口和一条已确认存在横向推进线索记录支撑，使其满足事件级交付标准。

然而，“确认安全事件”并不等同于已证明攻击者实现整体控制链闭环、持久化驻留或数据外传。本次研判的把握度为 94%，剩余不确定性主要来自候选扩线事件仍需独立验证、外部基础设施缺乏公开情报校准，以及一批反证与替代解释尚未被排除。下文将在深入分析主证据链后，对这些边界和不成立结论逐一展开。

## 2. 事件过程与关键时间线

事件起点为 2026-07-14 01:04:00 UTC，资产 ws-eng-02（源地址 10.70.3.12）首先解析了域名 sync-cdn-notify.net。该域名被标记为稀有解析，且在分析窗口内从未出现在正常业务基线中。紧随其后，在 2026-07-14 01:10:00 UTC，同一资产触发种子 TLS 告警，目标为 203.0.113.77，JA4 指纹 t13d1516h2_2ba4190accc0_13fe129f5abc 再次命中，通信对象指向同一域名与 IP 的基础设施对，构成一条完整的可疑信标。

后续时间线上存在若干待验证扩线事件，包括 ws-eng-05 在 01:32:10 UTC 解析另一个稀有域名 cdn-notify-edge.net，并在 01:36:00 UTC 进一步连接至该域名关联的 IP 198.51.100.44。此外，在 01:39:20 UTC 出现一条由 ws-eng-05 向 ws-eng-09（10.70.3.90）发起的 WMI 远程进程创建告警。上述候选事件尚未完成独立验证，仅作为扩线边界存在，当前不能纳入已确认传播范围。

## 3. 关键证据判断

当前结论成立的核心原因在于，主证据链并非仅由一条孤立告警构成，而是形成了一个可追溯、可重复观测的行为闭环。ws-eng-02 在种子告警前就已完成对 sync-cdn-notify.net 的 DNS 解析，解决了“告警前是否存在信标准备”的疑问；告警后不足五分钟内出现重连，排除了临时误报的可能性；且重连后仅 4 分钟内发生 rundll32.exe 可疑执行，将“通信异常”与“主机执行”连接起来。随后出现的 PsExec 远程服务创建并非孤立的横向移动告警，它被随后 ws-eng-05 对同一 C2 基础设施的主动连接所佐证，这种从源主机到目标主机再到目标主机回连 C2 的逻辑链，是本次事件成立的压舱石。

尽管如此，更强结论，例如“已观察到完全控制 ws-eng-02 与 ws-eng-05”或“已实现持久化与数据外传闭环”，当前尚不成立。首先，可疑执行事件虽显示 rundll32.exe 从用户可写路径加载 DLL，但缺少命令行参数、落地文件完整路径、父子进程关系及内存取证等更深入的主机执行上下文。其次，PsExec 远程服务创建被观测到，但尚未与 ws-eng-05 上的具体落地载荷或持久化机制形成直接对应，这也意味着横向移动的“成功落地”环节仍欠一步主机侧核查。此外，seed 家族提示“Suspected multi-host beacon spread”虽然与当前事件方向吻合，但其外部技术背景尚未完成公开情报校准，不能作为强归因依据。这些限制将在后续反证与缺口分析中详细说明。

## 4. 影响范围、候选对象与外部基础设施

当前可以纳入受影响范围并建议立即隔离与取证的资产是 ws-eng-02 与 ws-eng-05。ws-eng-02 是此次事件的种子资产，承担了初始信标、重复连接、可疑执行以及横向移动起点的角色，其对 C2 基础设施的通信时间最早，行为链条最为完整。ws-eng-05 作为横向移动的直接目标，随后主动回连同一 C2 基础设施，使其从候选资产上升为已确认受影响资产。需要再次强调，此处“受影响”是指资产在时间序列上表现出与 C2 基础设施的关联行为以及被远程服务操作触及，不等于已证实攻击者获得完全控制或在该主机上完成后续载荷释放。

候选范围内，资产 ws-eng-09 对应的内部地址 10.70.3.90 仅在一条背景解释事件中被提及，且该事件（WMI 远程进程创建告警）因缺少可独立验证的指示物，当前仅作为边界线索保留，不能纳入已确认影响范围。此外，两条待确认的候选网域 cdn-notify-edge.net 与 IP 198.51.100.44，尽管与 ws-eng-05 的后续行为相关，但同样因尚未命中独立情报或本地指纹，只能作为排查和封禁的候选指标，不能被视为已确认 C2 资产。

在外部基础设施方面，已确认的主证据链反复指向两个对象：IP 203.0.113.77 与域名 sync-cdn-notify.net。这两者构成了此次事件中最核心的关联外部基础设施，建议在通报、边界封禁与持续监控策略中将其列为高危外联对象，但不能将其写作“受影响资产”。背景中出现的 download.windowsupdate.com 与 IP 13.107.246.45 已关联至 Windows 更新业务，与本次事件主链无关，不属于关联外部基础设施。

本次分析中出现的多起背景事件和替代解释虽不至于推翻主链结论，但它们有效限制了“攻击者完全控制链”等更强断言。在 ws-eng-05 上，观测到与 SCCM 补丁分阶活动相关的资产上下文事件，以及到 download.windowsupdate.com 的合法更新流量，时间窗口与可疑活动存在部分重叠。虽然合法补丁流量不能解释 PsExec 来源或对 203.0.113.77 的 TLS 信标，但它提示：如果 ws-eng-05 上存在 WMI 或 PsExec 的例行管理使用，那么横向移动告警的解释需要更谨慎地排除管理脚本干扰。同样，候选域名 cdn-notify-edge.net 与 IP 198.51.100.44 在本地情报中暂未命中恶意标记，增加了它们可能是共享 CDN 或边缘基础设施的概率，进一步暗示不应在此时将它们直接定为恶意资产。
