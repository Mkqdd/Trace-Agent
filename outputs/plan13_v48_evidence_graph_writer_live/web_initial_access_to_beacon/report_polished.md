当前结论的核心支撑在于一条在时间、逻辑和实体关联上都高度连贯的证据链。种子告警本身已经携带了明确的恶意行为判定 Confirmed web initial access to beacon chain，而围绕它的前后事件构成了一个自洽的攻击叙事。在告警发生前五分钟，同一台主机 web-app-01 刚解析了信标域名 cdn-auth-check.net，告警发生后两分钟，该主机又立即向同一外部 IP 和域名发起了重连。这种“解析-告警-重连”的短时序模式，有力地将初始的漏洞利用行为与后续的信标通道建立绑定在一起，排除了孤立告警的可能性。

WebShell 文件 shell.aspx 的落地和 PowerShell 启动器的执行，为“Web 初始接入”到“命令执行”提供了关键的主机侧实物证据和进程行为证据。这些事件在时间上紧随外部信标通信，在路径上都指向 /var/www/html/.cache，逻辑上环环相扣。更关键的是，从 web-app-01 到 app-db-01 的 SMB 连接，以及 app-db-01 随后立即向攻击者基础设施发起的信标通信，将横向移动从网络连接猜测提升到了目标主机外联确认的层面。这使得 app-db-01 可以且应当被纳入已确认的受影响范围，需要隔离和取证。

然而，必须明确当前证据链的边界。尽管攻击链完整，但 web-app-01 上脚本块日志被禁用的事实，使我们无法掌握 PowerShell 启动器执行的具体命令内容，因此不能断言攻击者在主机上完成了哪些具体操作。同样，由于缺少持久化机制（如计划任务、服务注册、启动项）的证据，以及尚未对 web-app-01 到 app-db-01 的远程服务创建等候选横向移动事件完成独立验证，目前不能得出“已观察到实现对环境的完全控制”或“已建立长期持久化驻留”的更强结论。本地情报库未命中相关指示物，也从侧面提示这可能是一个未被现有签名体系覆盖的定制或变种工具。
