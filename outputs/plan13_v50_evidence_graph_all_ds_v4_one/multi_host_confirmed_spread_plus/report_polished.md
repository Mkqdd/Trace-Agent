## 1. 事件结论与当前判断

本次调查围绕种子资产 ws-eng-02 上触发的 "Suspected multi-host beacon spread" 告警展开，在 2026-07-14 01:04:00 UTC 至 2026-07-14 01:28:40 UTC 的分析窗口内，共检索到 6 条偏可疑事件，全部围绕域名 sync-cdn-notify.net、外部 IP 203.0.113.77 和内网 IP 10.70.3.45 形成闭合证据链。本地情报库未命中相关指示物，但事件簇已从单点异常推进到多资产范围，主支撑证据和范围达到确认事件交付门槛。

当前判断为确认安全事件，严重度评定为高危，研判把握度为高。该结论基于已确认的主证据链：种子告警所揭示的可疑 TLS 信标、告警前后的 DNS 解析与重连行为、信标序列后的可疑执行事件、以及 PsExec 远程服务创建后第二台主机接入同一命令与控制基础设施的事实。需要特别注意，本结论并不等同于已确认攻击者完全控制、持久化驻留或横向移动闭环，报告的后续部分将具体阐述当前证据的上限与缺口。

## 2. 事件过程与关键时间线

事件起点为 2026-07-14 01:04:00 UTC，种子资产 ws-eng-02（源地址 10.70.3.12）解析了一个罕见域名 sync-cdn-notify.net。该 DNS 解析发生在可疑 TLS 会话前夕，构成了事件链的第一个信号。6 分钟后，即在 2026-07-14 01:10:00 UTC，ws-eng-02 与外部基础设施 203.0.113.77 之间建立了 TLS 通信，种子 JA4 告警命中了指纹 t13d1516h2_2ba4190accc0_13fe129f5abc，将该会话标记为可疑信标。

在告警触发后，ws-eng-02 于 2026-07-14 01:14:20 UTC 再次与同一命令与控制基础设施 sync-cdn-notify.net 和 203.0.113.77 建立连接，表明这是持续性的信标行为，而非单次异常。随后在 2026-07-14 01:18:00 UTC，ws-eng-02 上出现了可疑的 rundll32.exe 进程执行，从用户可写路径加载了一个装载器 DLL，该事件紧接信标序列之后发生，形成可疑的执行链线索。

更关键的是，在 2026-07-14 01:21:10 UTC，ws-eng-02 使用 PsExec 向 10.70.3.45（ws-eng-05）发起了远程服务创建操作。7 分钟后，即在 2026-07-14 01:28:40 UTC，第二台主机 ws-eng-05（源地址 10.70.3.45）开始主动联系同一信标基础设施 sync-cdn-notify.net 和 203.0.113.77。至此，多主机信标传播的行为特征已经完整呈现。

## 3. 关键证据判断

当前结论之所以能够成立，核心在于证据链的时序连贯性和行为一致性。种子告警并非孤立事件：ws-eng-02 在告警前对罕见域名的 DNS 解析、告警后的重连行为、信标序列后出现的可疑 rundll32.exe 执行，以及 PsExec 远程服务创建后 ws-eng-05 立即接入同一外部基础设施，这五个事件构成了一个从命令与控制接触、信标维持、本地执行到横向传播的完整行为序列。JA4 指纹 t13d1516h2_2ba4190accc0_13fe129f5abc 作为种子命中指纹，将这一系列行为锚定在同一个通信特征上，而外部基础设施 sync-cdn-notify.net 和 203.0.113.77 在 ws-eng-02 和 ws-eng-05 之间的一致性，进一步排除了随机噪声的可能。

不过，当前证据链存在明确的上限。rundll32.exe 执行事件虽然提供了可疑执行线索，但目前缺少命令行参数、落地文件清单、父子进程链、持久化机制和内存取证证据，因此不能被判定为已确认的恶意软件完整执行。同样，PsExec 远程服务创建虽然高度可疑，且与 ws-eng-05 的后续信标行为存在时间上的紧密关联，但在没有 ws-eng-05 主机侧执行证据支撑的情况下，不应直接断定为已观察到实现横向移动闭环或已控制第二台主机。此外，种子告警所携带的 "Suspected multi-host beacon spread" 家族提示提供了有价值的辅助背景，但本地情报库未命中该指示物，外部技术背景尚未补充，因此仅能作为研判参考，不能等同于强归因。

## 4. 影响范围、候选对象与外部基础设施

已确认受影响资产包括 ws-eng-02 和 ws-eng-05。ws-eng-02 是整个事件链的起点，承担了最初的 DNS 解析、可疑信标通信、可疑执行和横向传播发起角色。ws-eng-05 在疑似 PsExec 远程服务创建后开始与同一命令与控制基础设施通信，已纳入主证据链，需要隔离和取证。两台主机的源地址分别为 10.70.3.12 和 10.70.3.45，这两个内网 IP 是关联内部地址，用于在日志检索中基于源地址进行关联分析，其本身不是受影响资产。

候选扩线对象包括 JA4 指纹 t13d1516h2_2ba4190accc0_13fe129f5abc 作为扩线候选指纹，可以用于在更大时间窗口内检索是否存在同指纹的其他通信。当前尚未显式展开此类扩展查询，因此同指标更大范围复现的可能性未被排除或确认，属于待验证线索。此外，ws-eng-05 上尚未获取主机侧执行证据，其在攻击链中的确切角色仍有待通过端点取证进一步澄清。

核心外部基础设施由域名 sync-cdn-notify.net 和 IP 地址 203.0.113.77 构成。这两个对象在 ws-eng-02 和 ws-eng-05 的信标通信中反复出现，是事件簇中外联的关键节点。需要注意，外部基础设施不能写成受影响资产，它们应作为外联对象和关联基础设施对待，是后续排查和封禁的重点对象。当前尚不能排除 sync-cdn-notify.net 背后是否存在 CDN 或共享代理层，其对外呈现的技术背景需要通过外部情报进一步确认。

## 5. 反证、替代解释与未闭合缺口

当前证据链中存在多个未闭合缺口和需要审慎对待的替代解释可能性，这些因素明确限制了对更强结论的推进。首先，sync-cdn-notify.net 域名字面上可能涉及内容分发或通知服务，在某些环境中可能与正常业务软件、云同步工具或 IT 管理平台的通信基础设施产生重合。虽然事件中的时序关联性和 PsExec 远程服务创建高度可疑，但目前尚未显式检查 ws-eng-02 和 ws-eng-05 上是否存在补丁窗口、计划任务、软件部署或共享管理基线等维护活动，这些可能构成部分边界信号的替代解释。如果 rundll32.exe 加载操作和 PsExec 活动与已授权的 IT 运维动作重合，则信标通信本身可能需要重新评估，尽管这种重合的概率在事实上较低，但在尚未显式排除之前必须作为边界条件呈现。

更具约束性的缺口来自主机侧证据的缺失。rundll32.exe 的可疑执行虽然被标记为执行阶段事件，但当前没有命令行参数、没有落地 DLL 文件的路径哈希、没有父子进程链的完整记录、也没有持久化机制如计划任务或注册表项。因此，即使信标行为已经确认，恶意软件是否完整执行、是否成功建立驻留、是否具备进一步指令执行能力，这些都无法在当前数据基础上做出肯定判断。同样，PsExec 远程服务创建的观测指向横向移动，但在 ws-eng-05 一侧没有对应的服务启动日志、进程创建事件或文件落地证据，这使得 ws-eng-05 的信标通信仍然存在其他可能性，例如通过其他传播途径或独立感染发生。另外，seed 自带的家族提示尚未通过外部情报补充获得技术背景支撑，本地情报库也为空命中，这些缺口共同将结论上限锁定在“确认多主机信标传播事件”这一层面，而不能提升为“确认攻击者控制链已闭环”或“确认存在横向推进线索已完成且持久化”。
