# 首页摘要

- **结论：** 确认安全事件
- **严重度：** 高危
- **研判把握：** 高 (94%)
- **已确认范围：** 内网资产 `web-app-01`（10.60.1.14）与 `app-db-01`（10.60.2.34），外部基础设施 IP `198.51.100.88` 与域名 `cdn-auth-check.net`
- **一句话结论：** 对外服务的 `web-app-01` 遭漏洞利用后植入 Webshell，进而加载 PowerShell 并横向移动至数据库服务器 `app-db-01`，两台主机均与同一组外部 Beacon 基础设施发生通信。
- **立即动作：** 立即隔离 `web-app-01` 与 `app-db-01`；在边界网络设备封禁 `198.51.100.88` 和 `cdn-auth-check.net`；对两台主机发起取证，重点采集内存与磁盘中 Webshell、PowerShell 执行痕迹。

## 1. 事件结论与当前判断

这是一起已确认的 Web 初始入侵并转向 C2 信标链的安全事件。种子告警及其周边事件构成一条可验证的时序链：Web 应用服务器 `web-app-01` 在对公网开放的登录接口遭到漏洞利用后，被写入了一个名为 `shell.aspx` 的 Webshell 文件；随后该服务器通过 PowerShell 执行进一步操作，并最终向数据库服务器 `app-db-01` 发起 SMB 连接与远程服务创建。两台主机先后多次解析并通信同一稀少域名 `cdn-auth-check.net` 及其解析 IP `198.51.100.88`，且通信指纹 JA4 判定命中“疑似 Webshell Beacon over TLS”告警。虽然当前尚未取得主机内存转储、完整持久化机制或攻击者直接键盘操作证据，事件链已充分支持“初始接入到 C2 链路已经建立，且具备横向推进特征”的确认级结论。本地情报库未命中 `cdn-auth-check.net` 或 `198.51.100.88`，但这并不削弱告警链的可信度，仅说明现有情报源尚不能对此基础设施给出已知归属。

  `app-db-01` 通过 `10.60.2.34` 主动联系 `cdn-auth-check.net` 和 `198.51.100.88`。这一现象表明目标数据库服务器也已获得与外联 C2 通信的能力，其通信行为与 `web-app-01` 的 Beacon 模式一致，确认受影响范围已从单一 Web 前端扩展到数据库层。

## 3. 关键证据判断

种子告警不仅给出一个告警名称，更重要的是它凭借 JA4 指纹 `t13d1517h2_91adbe210bc1_7cae1281e991` 将 TLS 加密会话识别为 Webshell Beacon 行为，这构成事件研判的基石。该指纹不是基于 IP 或域名的黑名单匹配，而是根据客户端 TLS 握手特征与被篡改的 Web 服务器出站行为所形成的可重现特征--由于同一指纹在 `web-app-01` 的后续连接中再次出现，又在 `app-db-01` 的独立出站流中复现，它把两台主机绑定在了同一组 C2 基础设施和同一组操作行为模式上。

漏洞利用成功与否不能仅凭 exploit 尝试来判定，但 `/var/www/html/.cache/shell.aspx` 的落盘时间和路径紧接在 exploit 请求之后，这为“利用成功并获得了文件写入能力”提供了物理证据。关联的 PowerShell 启动器在 w3wp 下执行、随后访问 Web 工作账户凭据存储，将告警链从“Web 控制”推向“主机执行与凭据接触”的危险阶段。凭据访问事件出现后，它使同一时间窗口内体现的 SMB 连接和远程服务创建不再仅仅是孤立的内网流，而具备凭据复用导致的横向推进逻辑。

从终端取证角度看，关键缺口在于 `web-app-01` 上脚本块日志已被关闭，限制了围绕 PowerShell 启动器重建完整命令行的能力。这意味着当前不能确认 PowerShell 是否下载了额外载荷或实现了内存驻留。然而，凭据访问、域名解析、Beacon 指纹与远程服务创建已经构成一条稳定且多维交叉的因果链，即便缺少脚本内容，也不足以否定已经发生的 C2 通信和跨主机推进。

## 4. 影响范围、候选对象与外部基础设施

已确认受影响的范围包括 `web-app-01`（10.60.1.14）和 `app-db-01`（10.60.2.34）。`web-app-01` 是事件起点与核心执行节点，上面发生了漏洞利用、域名解析、Webshell 落地、PowerShell 执行、凭据存储访问以及向数据库服务器的横向连接；`app-db-01` 则在接收 SMB 连接后独立解析并通信同一组外部基础设施，表明它不仅仅是横向移动的“路由经过点”，而是已经具备自行联络 C2 的能力，需要作为已确认受影响资产进行隔离取证。

存在一个明确的候选扩线资产 `web-app-03`（10.60.1.23）。在 2026-05-11 14:45:20 UTC，该主机通过扫描器 CDN 域名 `scanner-cdn.example` 联通了同一基础设施 IP `198.51.100.88`。这一通信路径与攻击链使用的 `cdn-auth-check.net` 不同，且涉及已知的扫描器遥测供应商域名，使其更可能属于共享托管或扫描器背景流量。当前 `web-app-03` 尚未出现 Webshell、PowerShell 执行或凭据访问等相应主机侧事件，该主机只应作为待核查候选资产保留，不能直接并入已确认受影响范围。

外部基础设施由 `cdn-auth-check.net` 和 `198.51.100.88` 组成，二者在 `web-app-01` 和 `app-db-01` 的 DNS 解析和加密 Beacon 流中反复出现，既作为 C2 信标目的地，也作为横向移动后数据库服务器首次主动外联的目标。IP `198.51.100.88` 还通过扫描器供应商域名在 `web-app-03` 上出现，但这一事实不能削弱该 IP 作为攻击设施的角色，仅说明同一托管地址可能承载多种服务，给边界封禁和回溯带来需要去噪音的复杂性。域名 `scanner-cdn.example` 本身不是攻击设施，仅作为帮助区分恶意通信与正常扫描器流量的背景对象。

## 5. 反证、替代解释与未闭合缺口

存在若干背景现象，可将某些结论的强度限定在当前水平，但不能推翻主事件链。在 2026-05-11 14:04:40 UTC，WAF 遥测显示同一时间窗内 `web-app-01` 收到了被拦截的通用扫描器载荷，这一事实可能解释部分告警噪音，但它发生在种子 Beacon 告警之前，且扫描器 payload 与后续 Webshell 写入和 Beacon 特征在行为模式、时间和互斥性上都存在明显差异，不会与核心攻击链混淆。

另一项需要重视的背景是，`web-app-01` 在 2026-05-11 14:50:00 UTC 启动了计划的 Hotfix 部署。该维护窗口落在可疑链之后，用来解释后续的服务重启变动是合理的，不应据此反推整个 Webshell-PowerShell-C2 行为链为维护侧效应。同样的保守态度适用于 `web-app-03` 上通过扫描器域名联通 `198.51.100.88` 的事件：该事件提示可能存在共享托管或供应商遥测对外部 IP 的正常访问，但这不能解释 `web-app-01` 和 `app-db-01` 反复通过 `cdn-auth-check.net` 发起加密 Beacon 的行为，因此仅作为一个共享基础设施背景保留。

未闭合缺口直接影响判断上限。在横向移动环节，`web-app-01` 至 `app-db-01` 的 SMB 连接和远程服务创建虽然形成推进信号，但尚未补上目标主机 `app-db-01` 侧对应的进程执行、文件落地或权限提升证据；同样，`app-db-01` 对外发出的信标流背后，是否由驻留程序、计划任务或内存模块发起仍属未知。这一缺口限制了将横向移动闭环为“已观察到两台主机间完全贯通并独立执行”的更激进结论。另一缺口是围绕 `cdn-auth-check.net`、JA4 指纹和“Confirmed web initial access to beacon chain”家族提示的公开技术背景尚未充分收集，导致当前尚未研判出明确的攻击工具族归属，也无法判断该基础设施是否为已知平台代管实体，从而影响归因维度的深度。基于 关键关联指标 扩线产生的 12 条关联事件尚未完成独立验证，其是否为同一事件簇的衍生扩面，仍是待闭合的候选问题。同时也仍需要围绕当前 关键关联指标 做一次显式扩线，以确认同指纹或同域名在同时间窗内是否存在更大范围的资产复现，这将直接决定范围是否需要升级。

## 6. 处置建议与后续核查

- **隔离与取证 `web-app-01` 和 `app-db-01`**  
  通过 EDR 或手动操作立即将两台主机断网隔离，保留内存转储和磁盘镜像。重点取证路径：`web-app-01` 上的 `/var/www/html/.cache/shell.aspx`、该文件的时间戳与哈希，w3wp 进程对应的 PowerShell 命令行日志文件、计划任务和服务注册表项；`app-db-01` 上需关注是否存在新增的远程服务、计划任务或与 `cdn-auth-check.net` 通信的派生进程。目标是在保留内存证据的前提下，确认 Webshell 是否被加载、凭据是否被导出、持久化机制是否已建立。

- **边界封禁与出口回溯：`198.51.100.88` 和 `cdn-auth-check.net`**  
  在边界防火墙、Web 代理和 DNS 递归服务器上增加针对 IP `198.51.100.88` 和域名 `cdn-auth-check.net` 的阻断规则。同步提取防火墙/代理的完整出站流量日志，以 ` 目标 IP=198.51.100.88` 或 `dns_query=cdn-auth-check.net` 为检索条件，回溯分析窗口前后 7 天的访问记录，确认是否有其他内网资产曾解析该域名或直连该 IP。DNS 日志中应关注源 IP、查询时间戳和是否收到 A 记录响应。

- **围绕 JA4 指纹进行环境内扩线**  
  在流量传感器或 NDR 平台对 JA4 指纹 `t13d1517h2_91adbe210bc1_7cae1281e991` 执行全量搜索，时间窗口覆盖分析窗口前后至少 48 小时。验证目标：检出任一内网源 IP 发起的命中该指纹的 TLS 会话，尤其是那些同时指向 `198.51.100.88` 或其它解析到该段地址的会话，并将结果与当前已知受影响的 `10.60.1.14` 和 `10.60.2.34` 列表对比，辨识是否存在尚未纳入的受影响资产。

- **验证候选资产 `web-app-03` 的涉事程度**  
  针对 `10.60.1.23` 提取其进程创建日志、网络连接日志和 DNS 查询日志，检索条件包括对 `198.51.100.88`、`cdn-auth-check.net`、`scanner-cdn.example` 的访问，以及是否存在 `shell.aspx`、`w3wp` 异常子进程或凭据存储访问事件。验证目标：判断该主机是否具备任何与主事件链一致的 Webshell、PowerShell 执行或凭据访问行为；若无，则保留为候选边界，若有命中则应立即纳入确认受影响范围并执行隔离取证。

- **完成关联事件独立验证**  
  对扩线得到的 12 条候选事件逐条进行独立研判。验证应结合流量侧日志（源 IP、目的 IP/域名、时间戳、字节数、JA4 指纹）和主机侧 EDR 记录（进程、文件写入、凭据访问）；任一候选事件若同时命中 `cdn-auth-check.net` 或 `198.51.100.88` 且具备主机侧执行或 Web 写入特征，即应按照事件升级流程将其并入主范围处置。

- **补全外部情报背景**  
  查询开源情报和商业威胁情报平台，检索 `cdn-auth-check.net`、`198.51.100.88` 和 JA4 指纹的历史使用记录，补充关于“Confirmed web initial access to beacon chain”家族提示的技术说明。验证目标：明确该基础设施是否关联已知 APT 组织、红队工具或恶意托管平台，用于决策后续是否向更高层级报送以及是否向托管方发起滥用投诉。

- **检查维护窗口与反证**  
  从变更管理系统调取 2026-05-11 14:50:00 UTC 前后的维护工单、Hotfix 编号和操作日志，核对其在 `web-app-01` 上触及的服务重启范围、文件变更清单和系统账户活动，与已知攻击事件时间线和文件路径进行比对，排除“shell.aspx”文件和 PowerShell 活动为维护脚本的可能性。同步检查补丁管理平台是否存在同一窗口内对 `app-db-01` 的计划操作，以确保横向连接的归属边界清晰。
