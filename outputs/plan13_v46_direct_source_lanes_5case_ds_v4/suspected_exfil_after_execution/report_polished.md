## 3. 关键证据判断

对事件成立起决定性作用的是种子告警及其后续主机活动构成的线性行为链。种子告警不仅带有 JA4 指纹 `t13d190900_44ac2200b3c1_ab11cd22ee44` 的匹配，还直接提示“疑似云存储外传链”，这种家族提示虽然不能单独做归因，但在本地情报库未命中该指示物的背景下，它为后续证据提供了分析框架。真正让事件从疑似升级为确认的是在告警之后两分半钟内出现的 PowerShell 调用、7z 打包、文件暂存和约 640 MB 上传这一完整动作序列。

PowerShell 脚本 `sync.ps1` 的调用位置与用户配置目录相关，且之后立即发生项目文件归档和暂存，使得“脚本编排”成为最合理的解释。7z.exe 创建 `RND-Q2-prototype.zip` 的行为如果孤立出现，尚可被解释为合法备份，但它与后续暂存和数据外传的直接时序耦合，极大削弱了合法操作的可能性。进一步地，将 ZIP 暂存到伪装路径 `C:\Users\Public\Music\cache.dat`，并在短暂间隔后向同一存储边缘 IP 发出大量 TLS 上传，构成了用于躲避检测和数据外传的 TTP。

在该链之外，DLP 记录虽无法查看压缩包内容，但对传输大小和时间点的确认起到了旁证作用。同时，`api.files-sync-share.net` 的后续解析和 TLS 会话，说明该主机与远端基础设施之间存在多次交互，增加了疑似 C2 通道的连续性。在证据完整性缺失方面，EDR 未能保留完整 PowerShell 命令行的限制主要表现在它令脚本逻辑无法完全还原，这限制了我们将执行链中的所有细节写死为“已确认执行恶意载荷”。不过，这一缺口并未动摇把 ws-rnd-04 纳入确认受影响范围的判断，因为执行结果（打包、暂存、上传）已被下游行为明确观测，且行为模式与脚本编排高度一致。

此外，本地情报库未命中指示物也限制了将事件直接归因到特定已知威胁组织的能力。随之引入的候选技术来源（如向云存储外传 T1567.002、通过 C2 通道外传 T1041 等）为理解攻击子阶段提供了参考，但不能直接替换为确认的 ATT&CK 技术链。这些结论性约束整合后，我们的判断上限是：已确认一次有组织的外传行为，且攻击链至少覆盖了指令下发／脚本执行、数据打包和加密上传，但尚未延伸到持久化、横向移动或攻击者完全控制主机阶段。

## 4. 影响范围、候选对象与外部基础设施

目前已确认纳入受影响范围的资产为 ws-rnd-04。该资产上出现了从域名解析、TLS 信标、PowerShell 执行到数据打包和最终外传的完整主链，是本次事件中唯一在主机侧和网络侧均留有可验证证据的节点。确认范围以该资产的通信行为和数据泄露行动为边界，并不等价于已观察到该主机上完成持久化或获得不受限的系统控制。

待确认的候选对象包含 ws-rnd-09 和 ws-rnd-12。ws-rnd-09 在 2026-06-03 17:05:00 UTC 向 `files-sync-share.net/198.51.100.144` 发起过一次短连接，但缺失主机侧证据，且后续调查发现它在同一小时内存在已批准的备份任务，其存储类流量可能由该作业产生，因此不能直接将其纳入受影响范围。ws-rnd-12 在同一 IP 通过另一个不同厂商 CDN 域名 `filesync-cdn.example` 进行了访问，这提示 198.51.100.144 并非专门用于恶意的独立基础设施，同时该主机本身也未出现异常执行或文件活动，只能保留在候选边界中。对于这两台资产，当前证据仅能支撑“候选关联”，能否并入确认范围，取决于进一步主机取证和 EDR 回溯的结果。

事件中反复出现的外部基础设施包括 IP 地址 `198.51.100.144`、域名 `files-sync-share.net` 及其子域名 `api.files-sync-share.net`。这些对象在主证据链中出现在 TLS 信标、HTTPS 上传、与上传后会话等多个节点，构成可疑存储 / 命令通道的出口侧。由于部分域名仅在本次观察窗口内被罕见解析，且存在共享 IP 现象（同一 IP 承载不同 CDN 域名），它们应作为排查和封禁对象处理，而不能直接推导该 IP 或域名全部用途均为恶意。此外，正常的企业 SharePoint 同步流量（`company-my.sharepoint.com`）以及相关 IP `13.107.136.9` 在 ws-rnd-04 的观察窗口中也存在，这在技术上将“互联网存储流向”这一总体现象稀释为云常规使用与可疑外传并存局面，因此进一步巩固了仅对外联对象采取封禁与回溯，而不是扩大资产受影响范围的决策。

## 5. 反证、替代解释与未闭合缺口

存在数条反向证据或替代解释限制了更强结论的得出。第一，ws-rnd-09 的短连接虽与同一存储边缘有关，但它同时段运行的批准备份作业构成了存储流量的替代解释，使得该连接无法被独立定性为可疑活动。第二，ws-rnd-12 通过不同 CDN 域名 `filesync-cdn.example` 访问同一 IP `198.51.100.144`，反映出该 IP 可能属于共享基础设施或 CDN 节点，削弱了“该 IP 仅用于此次事件”的排他性判断，也因此不能将 IP 命中自动等同于横向传播。第三，ws-rnd-04 自身在调查窗口内存在向 `company-my.sharepoint.com` 的正常 SharePoint 同步流量，说明该资产日常就有向合法云存储的出站通信，因此在流量层面仅凭出站至存储基础设施一项无法独立确立恶意性，必须依赖行为链（信标、脚本编排、上传体量等）来区分。

未闭合缺口主要体现在两个方向。首先，仍未围绕当前 关键关联指标 指标（`files-sync-share.net`、`api.files-sync-share.net`、198.51.100.144）在全网范围执行扩线查找，因此不能排除存在其他工作站也向同一基础设施完成数据外传但未被现有事件簇覆盖。其次，尚未系统性地核对维护窗口、补丁部署、系统基线变更或共享备份策略等可能解释部分主机行为的信息，这虽然不否定当前主链，但限定了事件判定的上限，使其不足以自动推论整个研发网段均受影响。

在主机侧，EDR 未保存完整 PowerShell 命令行是最直接的分析缺口，使得暂存脚本的精确意图、是否包含持久化机制、是否进行内部发现或后续工具下发都处于未闭合状态。由于脚本动作触发了下游行为且外传完成，我们当前将其视为独立的外传链，但不能断言该脚本仅用于一次性外传。
