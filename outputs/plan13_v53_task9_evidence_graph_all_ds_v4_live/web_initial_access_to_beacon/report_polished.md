## 1. 事件结论与当前判断

本次事件基于一条 seed alert `Confirmed web initial access to beacon chain` 触发，经 关键关联指标 扩线和聚类分析后上升为确认安全事件。已确认的主证据链覆盖 web-app-01 从初始访问到信标建立、恶意文件落地、执行与凭证访问，以及指向 app-db-01 的横向移动信号，最终由 app-db-01 再次外联至原始外部基础设施。整个过程服从清晰的时间顺序和一致的通信对象收敛，研判把握为高。

当前结论仅达到“确认安全事件”的交付门槛，即证据足以交付事件级结论。这并不意味着已确认攻击者在全部环节完成控制、恶意软件完整执行、横向移动闭环、持久化驻留或数据外传闭环。报告后续章节将对已确认受影响范围、候选扩线对象、外部基础设施以及限制更强结论的缺口与反证逐一展开。

## 2. 事件过程与关键时间线

2026-05-11 14:02:00 UTC，开放在公网的 web-app-01 开始收到指向其登录端点的利用请求，该流量在外部 TLS 通信启动之前即已出现。随后 14:04:40 UTC，同一时间窗内的 WAF 遥测显示出被阻断的通用扫描器载荷，该事件当前仅作为背景信息呈现，不能独立推翻主链。

14:07:30 UTC，web-app-01 对 cdn-auth-check.net 发起 DNS 解析，解析发生在利用请求之后。14:12:00 UTC，以同一资产为源端点的 seed JA4 告警触发，匹配到疑似 web-shell 的 TLS 信标通信，对端为 cdn-auth-check.net / 198.51.100.88，种子命中指纹 `t13d1517h2_91adbe210bc1_7cae1281e991`。14:14:10 UTC，web-app-01 再次外联同一组外部基础设施，形成信标复现。

14:16:30 UTC，web-app-01 在 /var/www/html/.cache 路径下出现名为 shell.aspx 的 web-shell 文件，文件出现时间点在利用流量之后。14:18:10 UTC，PowerShell 启动器在 w3wp 进程下执行，并访问了同一临时 web 缓存路径。14:21:00 UTC，同一 web 工作账户对凭据存储进行了访问，紧跟在 PowerShell 启动器之后。

14:24:20 UTC，web-app-01 向 10.60.2.34 发起 SMB 连接，该连接紧随 web-shell 与 PowerShell 活动之后出现，构成横向移动信号。14:31:30 UTC，app-db-01 主动外联至 cdn-auth-check.net / 198.51.100.88，与原始信标基础设施一致。该行为紧接在横向移动信号之后出现，使 app-db-01 以确认状态纳入受影响资产范围。

上述时间线中，从利用请求、DNS 解析、信标通信、文件落地、执行、凭据访问到横向移动和外联收敛，事件推进具有明确时序和对象一致性，构成当前确认主链。

## 3. 关键证据判断

当前结论建立在一条闭合的确认主链之上：seed alert 自带家族提示指示这是一个已确认的 web 初始访问到信标链事件，而 main_chain 证据图将 9 条偏可疑事件聚合在 cdn-auth-check.net、198.51.100.88 和 10.60.2.34 的收敛范围内。从初始利用到信标建立、文件落地、执行与凭据访问再到横向移动的整个过程均可通过 confirmed 事件事实追溯，且所有事件均与同一组外部基础设施或同一内网 关键关联指标 地址相关，排除了孤立噪声的可能性。

证据链中最关键的环节在于：第一，seed 告警不仅是单点检测信号，其命中的 JA4 指纹 `t13d1517h2_91adbe210bc1_7cae1281e991` 具备工具或家族特征，提高了信标通信的可信度；第二，shell.aspx 的落地时间与路径位置与利用阶段吻合，随后 PowerShell 启动器即访问同一路径，又将凭据访问事件串联在同一个执行上下文中；第三，从 web-app-01 到 app-db-01 的 SMB 连接与 app-db-01 对同一外部基础设施的回连在时间上紧密衔接，使 app-db-01 的外联行为不再被视为孤立或无关通信，而是与前序事件具有业务逻辑上的关联。

同时必须指出，现有证据不足以支撑攻击者完全控制、恶意软件完整执行链闭环、持久化机制确认或数据外传闭环等更强结论。执行侧目前仅观察到 PowerShell 启动器和 SMB 连接，尚缺乏命令行参数、落地文件反查、父子进程链、持久化注册、服务创建或内存取证等主机侧证据。凭据访问虽然出现在事件链中，但未明确凭据的类型、范围与被利用方式。这些缺口将在第 5 节进一步展开。

## 4. 影响范围、候选对象与外部基础设施

已确认受影响范围目前纳入 web-app-01 和 app-db-01 两台资产。web-app-01 是种子告警的直接承载资产，经历了利用请求、web-shell 落地、信标通信、进程执行和凭据访问，是整个事件链的起点。app-db-01 在横向移动信号之后直接外联至相同的命令与控制基础设施，其行为与前序事件在时间和通信对象上高度一致，因此纳入确认受影响范围。需要说明的是，app-db-01 的外联行为虽然已确认发生，但目前缺乏该资产上的执行证据、文件落地证据或进程证据，其受影响的具体程度需要在主机侧进一步取证确认。

候选扩线对象包括内网地址 10.60.2.34 以及种子命中的 JA4 指纹 `t13d1517h2_91adbe210bc1_7cae1281e991`。10.60.2.34 在事件链中交替作为横向移动的对端和后续外联的源端点出现，但目前仅以事件形式存在，尚未落到独立确认的资产对象与主机侧追踪，因此仍视为候选范围内待验证的 关键关联指标。同一 JA4 指纹作为扩展查询候选，可用于发现在同一时间窗内是否存在其他受信标通信影响的资产，但不能在确认前写入已确认受影响范围。

核心外部基础设施包括 IP 198.51.100.88 和域名 cdn-auth-check.net。二者在主证据链中反复出现，是多条 confirmed 事件的外联对端，也是 seed 信标告警的指向对象。外部基础设施只能作为外联对象、关联基础设施或排查封禁对象纳入报告，不能将其描述为受影响资产。同样，内网地址 10.60.1.14 作为 web-app-01 上多数事件的源端点，其为关联内部地址，其角色需要结合 NAT、代理或日志采集架构进一步核实，当前不应直接等同于攻击者入口节点或攻击源。

## 5. 反证、替代解释与未闭合缺口

在本次分析中，存在一条 WAF 告警记录的通用扫描器载荷被阻断的背景事件，时间为 2026-05-11 14:04:40 UTC，源地址同为 10.60.1.14。这一事件有可能指示同一源地址的部分活动属于非定向扫描，但该解释不能延展至整条信标链：后续的 web-shell 落地、PowerShell 执行、凭据访问和横向移动均具有明确的目标指向性与执行逻辑，与通用扫描在行为模式上存在本质区别。因此，该 WAF 扫描器事件只能作为背景存在，其作用在于提醒我们不能将同一源地址的所有通信都简单归因为恶意攻击链，而不能推翻当前已确认的主线结论。

当前仍有多个缺口限制更强结论的可达性。首先，主机侧执行链仍不完整：PowerShell 启动器虽然已观测到进程存在并访问 web 缓存路径，但其命令行、父子进程、内存映像与持久化手段缺位，这直接限制了对恶意软件完整执行链和持久化驻留的确认。其次，横向移动仅体现为 SMB 连接与 app-db-01 的后续外联，横向所使用的凭据、协议内具体操作以及 app-db-01 端是否被成功执行或落地的证据尚未取得，因此不能确认存在横向推进线索闭环。再次，受限于当前未围绕 关键关联指标 做全面扩线检索，无法排除其他同指纹或同基础设施的资产是否也已受影响，也无法确认外部基础设施的技术背景是否能支撑更强的家族或工具归因。此外，关于维护窗口、基线变更或共享服务等良性替代解释的检查也尚未完成。这些缺口均已在假设板中标记，未来需按补充验证路径逐步闭合，当前阶段报告必须在此边界内保持结论的保守性。

- **app-db-01 主机侧补盲**：对 app-db-01 采集进程启动日志、文件创建日志和安全审计日志，重点确认是否出现类似 web-shell 或 PowerShell 启动行为。排查对象为 app-db-01 的操作系统审计和 EDR 传感器，验证目标为确认当前确认的外联行为是否伴随本地执行证据，以及该资产是否已被用于进一步横向移动或凭据外传。
- **凭据泄露影响评估**：核查 web 工作账户在 web-app-01 上所访问的凭据存储类型与权限范围，排查该账户在前后时间窗内的认证日志。排查对象为域控制器认证日志、凭据管理器审计和应用程序日志，验证目标为明确是否存在凭据已经外传或被滥用于其他系统的迹象。
