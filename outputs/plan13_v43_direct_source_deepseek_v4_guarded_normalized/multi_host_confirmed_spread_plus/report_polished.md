## 1. 事件结论与当前判断

本事件已满足“确认安全事件”交付门槛。种子告警在 2026-07-14 01:10:00 UTC 被触发，并自带家族提示 `Suspected multi-host beacon spread`。在分析窗口 01:04:00 UTC 至 01:47:30 UTC 内，已确认多台资产与同一套外部基础设施存在周期性加密通信，且通信后紧接出现可疑主机执行行为和向内网其他系统的远程服务创建操作。虽然本地情报库未直接命中该基础设施的已知恶意标记，但由于信标特征、时序关联和多步攻击行为的高度一致性，得出了该事件真实成立的结论。当前判断不要求攻击者已完全控制所有受影响主机或已实现闭环横向移动，而是确认存在足以构成事件级威胁的多阶段攻击活动。

在事件簇中仍有将 `ws-eng-09` 串联进来的候选扩线事证，但其基础验证尚不充分；同时，`ws-eng-05` 在信标前后存在经批准的 SCCM 补丁维护窗口操作，这些背景限制了我们在“已确认存在横向推进线索”和“已确认受影响”判断上做更强延伸。综合来看，事件判定焦点集中在命令与控制通信、可疑执行链和跨主机活动上，而攻击者持久化、数据窃取等更深度控制行为，仍需进一步取证闭合。

## 3. 关键证据判断

种子告警所呈现的 TLS 会话并非孤立异常，而是被前后多条事实赋予了明确的 C2 和攻击演进含义。首先，`ws-eng-02` 在告警前 6 分钟主动解析了稀有域名 `sync-cdn-notify.net`，这种在极短时间窗内完成解析并立即建立加密会话的流程，符合信标式 C2 通信的典型行为。该域名和对应的 IP `203.0.113.77` 在事件簇中反复出现，且两台不同资产 `ws-eng-02` 与 `ws-eng-05` 在各自的事件链中均主动连接该基础设施，由此产生了双重汇聚：同一套基础设施被多台内网主机依赖为通信锚点，这在内部资产层面构成了可靠的受损一致性判断。指纹 `t13d1516h2_2ba4190accc0_13fe129f5abc` 的命中进一步为此通信提供了可复现的技术特征，使得围绕该 JA4 指纹进行回溯扩线成为可能，而不必完全依赖域名或 IP。

另一方面，`ws-eng-02` 上在信标之后出现的 `rundll32.exe` 加载行为，提供了从 C2 通信通往主机执行的关键一步。该执行之所以判定为“可疑”而非直接确认恶意软件加载器，是因为事实中未给出完整命令行、所加载 DLL 的落地路径和文件哈希，也未提供该 `rundll32` 实例的父进程证据。因此，当前证据足以说明“执行很可能发生”，但尚不足以证明“恶意载荷已被成功加载并运行”。同样的逻辑被应用到 PsExec 活动上：`ws-eng-02` 到 `ws-eng-05` 的远程服务创建紧随信标之后，且 `ws-eng-05` 在短时间内接入同一 C2 基础设施，这一时序关系把“远程服务创建”从单纯的管理行为提升到高度可疑的横向推进线索。但在未获得 `ws-eng-05` 主机侧对应的进程启动日志、载荷写入证据或独立执行痕迹之前，不能将其定性为“已确认存在横向推进线索到 `ws-eng-05` 并成功执行”。

## 4. 影响范围、候选对象与外部基础设施

已确认受影响资产目前明确界定为 `ws-eng-02` 与 `ws-eng-05`。`ws-eng-02` 作为种子资产，全程承载了初始 C2 解析、TLS 信标和可疑执行，通过自身行为即可独立进入确认范围。`ws-eng-05` 则因为两条相互强化的线索被纳入确认范围：其一，它在 `ws-eng-02` 发起 PsExec 远程服务创建后不久便主动连接了完全相同的 C2 基础设施 `sync-cdn-notify.net` / `203.0.113.77`；其二，该外联行为与 PsExec 活动的时序高度相邻，且缺少任何证明该连接属于例行维护或已知良性服务的证据。尽管 `ws-eng-05` 在同一小时存在 SCCM 补丁和 Windows 更新背景流量，但这些维护活动不能直接解释向恶意基础设施的信标连接，因而仅对将该主机上所有的远程操作归因于攻击者形成限制，并未动摇其在受影响范围中的定位。

`ws-eng-09` 当前只能作为待核查候选资产处理。该主机出现在若干背景事件和候选事件中，包括被 `ws-eng-05` 通过 WMI 发起远程进程创建、解析候选域名 `cdn-notify-edge.net`，以及在 01:47:30 UTC 直接连接 `cdn-notify-edge.net` / `198.51.100.44`。然而，WMI 事件本身缺少可独立验证的指示物，`cdn-notify-edge.net` 也未完成情报命中验证，且 `198.51.100.44` 被后续事实证实为共享基础设施 —— `ws-lab-02` 的遥测作业通过正常域名同样访问了该 IP。因此，目前`ws-eng-09` 仍缺少并入确认范围所需的独立证据，它仅作为可能被推进的潜在候选边界保留。

外部基础设施层面，`sync-cdn-notify.net` 和 `203.0.113.77` 是贯穿全部确认事件的核心外联节点，在报告中作为外联对象和出口封禁操作目标出现。域名 `cdn-notify-edge.net` 和 IP `198.51.100.44` 仅作为候选扩展指标与共享基础设施线索出现，不应直接标记为“失陷设施”，应配套进行进一步外部情报关联后再决定是否纳入阻断列表。来自 Microsoft 的 `download.windowsupdate.com` / `13.107.246.45` 以及 `telemetry-collector.example` 均为背景解释对象，不属于恶意设施。

## 5. 反证、替代解释与未闭合缺口

在确认 `ws-eng-05` 受影响时，最明显的干扰来自其上的合法维护窗口。经批准的 SCCM 补丁部署和 Windows 更新下载发生在与横向移动和信标活动同一小时内，这意味着如果有人试图仅凭远程服务创建或某些管理行为来主张攻击者已完全控制该主机，这种主张会被维护背景所削弱。然而，`ws-eng-05` 主动连接至 `sync-cdn-notify.net` / `203.0.113.77` 这一事实，已超出 SCCM 和 Windows Update 的行为范畴，因此维护窗口只能限制“将远程管理活动全归于攻击者”这一推断，却不能推翻该资产受波及的判断。

更大的不确定性集中在候选扩线上。`ws-eng-09` 及其相关事件之所以仍然停留在候选边界，是因为连接目标 `cdn-notify-edge.net` 和 IP `198.51.100.44` 均无法被独立情报直接印证为恶意，且 `198.51.100.44` 被发现承载了同一网络中其他非恶意遥测流量，明显为共享基础设施。这意味着即使 `ws-eng-09` 与该地址的通信出现在攻击链下游，也无法排除该连接是正常通信或误关联的可能性。WMI 远程进程创建事件同样因缺少命令行、目标执行结果等独立支撑而被视为边界线索。

还有数个缺口未闭合。围绕当前 关键关联指标 的更大范围复现尚需显式扩线，以确认是否有其他内部资产也出现在对 `sync-cdn-notify.net` 或同一 JA4 指纹的通信记录中。扩线所得的 2 条关联事件仍未独立验证，因此整体事件在横向扩散的最终边界上存在不可忽视的盲区。`rundll32.exe` 执行的完整参数、父进程和落地 DLL 文件尚未获取，导致无法将主机执行阶段从“高度可疑”上升到“已确认恶意软件运行”。这些缺口共同构筑了当前判断的上限：确认事件成立，但攻击者的执行完整度、持久化机制、横向扩散全貌和群控规模均不具备最终结论。

## 6. 处置建议与后续核查

- **立即隔离已确认受影响资产**：针对 `ws-eng-02` 与 `ws-eng-05`，在交换机 ACL 或 EDR 策略中施加网络隔离，仅允许必要的取证通道；同时通过 EDR 或 sysmon 日志捕获当前运行进程、服务、计划任务和持久化注册表键，验证是否存在内存注入、未知服务和启动项。

- **封禁并回溯核心外部基础设施**：在边界防火墙、安全 Web 网关和 DNS 递归解析策略中对 `sync-cdn-notify.net` 和 `203.0.113.77` 实施出站禁止；并在代理/DNS 日志中，以 `sync-cdn-notify.net`、`203.0.113.77` 以及 JA4 指纹 `t13d1516h2_2ba4190accc0_13fe129f5abc` 为检索条件，回溯至少过去 30 天的历史流量，验证是否存在更早的通信或更多受影响资产。

- **处置 `ws-eng-02` 上的可疑 rundll32 执行**：在 `ws-eng-02` 上提取与 `rundll32.exe` 调用相关的 Windows 安全事件 4688 或 Sysmon 事件 1，获取完整命令行参数、父进程路径和进程链；定位 `rundll32.exe` 加载 DLL 的文件路径，提取哈希并在 VirusTotal 或本地威胁情报平台查询；对用户可写路径下同时段写入的 DLL、脚本或可执行文件做全盘 YARA 扫描。

- **核查并限制 `ws-eng-09` 的候选边界**：针对 `ws-eng-09`，以 `cdn-notify-edge.net`、`198.51.100.44` 和 WMI 远程进程创建日志（Windows 安全事件 ID 4688 或 Sysmon 事件 3/10）为目标，核查该主机是否还存在与 `sync-cdn-notify.net` 的直接连接、相同 JA4 指纹命中的 TLS 会话或 `rundll32` 类似执行痕迹。验证目标是确定其是否仍应停留为候选边界，或是否已具备并入确认范围所需的独立证据。

- **补做 WMI 横向事件的独立验证**：针对 `ws-eng-05` 到 `ws-eng-09` 的 WMI 远程进程创建，提取 `ws-eng-09` 在告警时间窗内的进程创建日志，定位 WMI 生成的子进程及其命令行，确认父子关系是否指向恶意载荷，并查找是否存在落地文件或后续外联行为。

- **扩线排查同指纹及同基础设施复现**：以 JA4 指纹 `t13d1516h2_2ba4190accc0_13fe129f5abc`、IP `203.0.113.77` 和域名 `sync-cdn-notify.net` 为 关键关联指标，在网络流量传感器（如 Zeek、Suricata）或 EDR 网络日志中搜索同时间窗内的全内网出站匹配，逐一核对返回的资产是否已经纳入当前确认范围，防止攻击者利用其他内网主机维持备用通道。
